## 四种图型

| `type` | 长什么样 | 什么时候用 |
| --- | --- | --- |
| `'line'`（默认） | 折线 | 看趋势方向与波动 |
| `'area'` | 折线 + 填充到基线 | 强调「累计量」而不只是方向 |
| `'bar'` | 柱状，正负分色 | 离散的期间值（每月销量），高度可比 |
| `'winloss'` | **等高**的上下柱 | 只看成败：一串「赢赢输赢输」。高度会被数值大小干扰，所以这里刻意不表达大小 |

## 配置项

每一列一份，写在 `columns` 里，键是列 key：

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `type` | `SparklineType` | `'line'` | 见上表 |
| `field` | `string` | **列 key** | 数组存在行上哪个字段。同名时不用写 |
| `values` | `(row) => unknown[]` | — | 自己取数组，优先于 `field` |
| `range` | `'row' \| 'shared' \| [lo, hi]` | `'row'` | 纵轴范围，见下 |
| `markers` | `('first'\|'last'\|'min'\|'max')[] \| false` | `false` | 画哪些标记点 |
| `color` | `string` | `var(--vt-color-primary)` | 主色 |
| `negativeColor` | `string` | `var(--vt-color-danger)` | 负值颜色（`bar` / `winloss`） |
| `fill` | `string` | 主色 + 18% 透明 | `area` 的填充色 |
| `lineWidth` | `number` | `1.5` | 线宽 |
| `baseline` | `number` | `0` | 基线。`winloss` 用它分成败，可以是「及格线 60」 |
| `gaps` | `'break' \| 'skip'` | `'break'` | 空洞断开还是连起来 |
| `tooltip` | `boolean \| (ctx) => string` | `true` | 悬停提示 |

插件级还有 `defaults`（所有列共用的默认值，列上可覆盖）与 `padding`（默认 `[4, 4]`）。

## 纵轴范围：`'row'` 还是 `'shared'`

这是**唯一**需要想一下的选项。

| | 语义 | 什么时候对 |
| --- | --- | --- |
| `'row'`（默认） | 每行按**自己的**极值铺满 | 看的是每一行自己的形状。一列里混着「1 万」和「3」两个量级时只能用它 |
| `'shared'` | 整列共用一套极值 | 行与行**高度可比**。同量级的数据才有意义 |
| `[lo, hi]` | 写死 | 有业务上的绝对刻度（0~100 分、0~1 的转化率） |

默认给 `'row'` 而不是 `'shared'`：混量级的一列里，共享范围会把小的那些压成一条贴底的直线，
什么都看不出来 —— 而这比「不能跨行比较」更糟。

`'shared'` 要扫全部行算极值（O(行数 × 点数)），所以缓存了；缓存按**列表数组的引用**定 key，
换数据自然失效。

给了 `range` 但某一行的数据超出时**不裁剪**，让它画到框外被裁掉 —— 裁数据会把「爆表」
这件事藏起来，而那通常正是要看的。

## 几个刻意的取舍

| 情形 | 做法 | 为什么 |
| --- | --- | --- |
| 一个数都没有 | 格子**留空** | 画一条横线会被读成「全是 0」，而「没数据」和「数据是 0」在报表里是两件事 |
| 全是同一个值 | 平线画在**正中** | 贴上边或下边看起来像「一直在顶」，那是错的信息 |
| 只有一个点 | 放正中 | 孤零零贴左边框看着像渲染坏了 |
| `bar` / `area` | 纵轴范围**包含基线** | 否则一列全正数里最矮那根柱子是 0 高，看着像「这一期没有」 |
| 值正好等于基线 | 仍给 1px 高 | 同上 |
| 空洞（`null`） | 默认**断开** | 数据缺了就该看得出来缺了 |
| 52 根柱子 | 缝按比例留（25%） | 固定像素的缝在密集数据上会把柱宽吃光 |

## 悬停提示是唯一的读数途径

一格 28px 高放不下任何刻度，所以提示不是装饰。默认显示「第 n 个：值」，提示会**吸附到点上**
（而不是跟着鼠标走）—— 鼠标在两点之间时跟着鼠标会让人分不清读的是哪个点。

```ts
vtSparkline({
  columns: {
    weekly: {
      // 拿到行、点下标、该点的值、整串值与列定义
      tooltip: ({ row, index, value }) => `${row.name} 第 ${index + 1} 周：${value ?? '缺数据'}`,
    },
    pnl: { tooltip: false },  // 关掉
  },
})
```

空洞那一点说「无数据」，不显示 `null`。

## 读屏听到的是人话

SVG 本身 `aria-hidden`（念一串路径坐标毫无意义），格子上挂 `aria-label`：

> 6 个数据点，从 12 到 30，最低 8，最高 41

用 `aria-label` 而不是 `title`：`title` 会弹浏览器原生提示，和本插件自己的悬停提示叠在一起。
没数据的格子**不挂** `aria-label` —— 别让读屏念一个空图。

## 为什么不用 echarts

一格 120×28 的迷你图不需要坐标轴、图例、动画、事件系统。除了体积（echarts 最小打包是本包
全部代码的几十倍，而且会进你的 bundle），真正的问题是**每格一个实例**：一屏 40 行就是 40 个
实例带 40 个 `ResizeObserver`，而虚拟滚动会让它们每滚一屏全部创建销毁一遍。

真要接图表库画**大图**（选区出图）是另一回事 —— 那是同包里 `vtCharts` 的事，见下。

## 虚拟滚动下的三条硬约束

价值不在「画一条线」，而在它必须在渲染热路径上：

1. **不读布局。** 画布尺寸从 `col.width` 与 `getRowHeight()` 现算，绝不读 `td.offsetWidth`
   —— 那是同步回流，一屏 40 格就是 40 次，滚动肉眼掉帧。有一条测试专门盯这件事：断言
   `getBoundingClientRect` 的**接收者**里没有迷你图的格子
2. **缓存按引用定 key，不靠钩子清。** `onDataChanged` / `onColumnsChanged` 都在单元格重画
   **之后**才触发，靠它们清缓存会让换数据后的那一帧仍用旧极值画（表现是「换完数据第一眼
   曲线是扁的，随便点一下才对」）
3. **一个委托监听管全表。** 每格一个 listener 在行 DOM 复用下是复利：漏一次解绑就泄漏一个
   闭包，连着那一行的数据

## 实例 API

| 方法 | 作用 |
| --- | --- |
| `renderSparklineSvg(values, colKey?, geom?)` | 单独生成一段 SVG 字符串。给导出与打印用 —— 那两条路拿不到 DOM |
| `refreshSparklines()` | 丢缓存并重画。常态不需要（缓存按列表引用失效），给**就地改行**那种场景用 |

SVG 生成层也能脱离表格单独引：

```ts
import { buildSparklineSvg } from '@virt-table-pro/charts';

const svg = buildSparklineSvg([1, 5, 3], { width: 100, height: 30 }, {
  type: 'line', color: '#409eff', lineWidth: 1.5,
  domain: null, markers: [], baseline: 0, gaps: 'break',
});
```
