## 配置项

插件级选项，每一条都能在调用 `exportXlsx()` 时按次覆盖。

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `sheetName` | `string` | `'Sheet1'` | sheet 名。非法字符（`[ ] : * ? / \`）会被清掉、超 31 字符会截断、重名自动加 `(2)` |
| `filename` | `string` | `<sheetName>.xlsx` | 下载文件名，没写扩展名会自动补 |
| `withStyles` | `boolean` | `true` | 表头底色、边框、列宽、对齐、数字格式 |
| `freeze` | `{ rows?, cols? }` | — | 冻结窗格。`rows: 1` 的语义是**冻住表头**，见下 |
| `selectionOnly` | `boolean` | `false` | 只导当前选区（需装核心的 `vtCellSelection`） |
| `includeHeader` | `boolean` | `true` | 带表头 |
| `includeFooter` | `boolean` | `true` | 带合计行（核心 `showSummary` 算出来的那行） |
| `includeCollapsed` | `boolean` | `true` | 折叠起来的分组 / 树节点里的行也导出，见「折叠与导出」 |
| `merges` | `boolean` | `true` | 还原合并单元格 |
| `autoFilter` | `boolean` | `false` | 在表头行开筛选下拉 |
| `numberFormats` | `Record<string, string>` | — | 列 key → Excel 数字格式串，如 `{ amount: '#,##0.00' }` |
| `liveSummary` | `boolean` | `false` | 合计行写成活 `SUBTOTAL` 公式而不是死数字 |
| `compress` | `boolean` | `true` | 关掉产出不压缩的 zip（更大，但同样合法） |
| `creator` | `string` | `'virt-table'` | 写进文件属性的作者 |
| `theme` | `SheetTheme` | 中性灰 | 表头 / 合计行配色与日期格式 |
| `pdf` | `PrintDocOptions` | — | PDF / 打印的默认排版，`exportPdf()` 时可再覆盖 |
| `toolbar` | `boolean` | `true` | 装了核心 `vtToolbar` 时放一颗「导出」按钮（面板型：xlsx / 选区 / PDF） |

::: tip 与核心 vtExport 的按钮同时装
两颗按钮的 key 不同（`export` / `exportXlsx`），不会互相拒绝，但界面上并列两颗「导出」很怪。
同时装时给核心那颗传 `vtExport({ toolbar: false })`，把入口留给这一颗。
:::

`numberFormats` 刻意**不按 `cellType: 'number'` 自动加千分位** —— 核心那边 `number` 的语义
就是「原始值，不做千分位」（格式化是 `render` 的职责），这里替它猜一个格式只会让导出结果
与屏幕上不一致。

## 实例 API

```ts
await table.exportXlsx();                          // 真 OOXML
await table.exportXlsx({ selectionOnly: true });   // 只导当前选区
await table.exportXlsx({ sheets: [...] });         // 多 sheet，见下
await table.exportPdf({ landscape: true });        // 排版 + 唤起打印
const html = await table.exportPdf({ htmlOnly: true }); // 只要 HTML，不打印
```

两个都是 `async`：压缩走的是流式 API，等它落完才触发下载。

## 冻结窗格与表头层数

`freeze.rows` 数的是**表头**，不是 sheet 的物理行：

```ts
vtXlsx({ freeze: { rows: 1, cols: 2 } })
```

- 扁平表头 → 冻 1 行
- 两级分组表头 → **自动冻 2 行**（整个表头）

直接把用户给的数字当 sheet 行号，在分组表头下会冻错位置：第一层冻住了、第二层还跟着滚。
要按物理行数冻就自己把表头层数算进去。

`freeze.cols` 与表格里的 `fixed` 列**无关** —— 那是两套东西（`fixed` 是屏幕上的固定列，
这里是 Excel 里的冻结窗格），按你给的数字来。

## 合并单元格怎么还原

静态 `options.merges` 与列 `mergeKey` 产出的自动合并**都会还原**，走的是核心公开的
`getEffectiveMerges()`（它给的是段的真实起止，不受渲染窗口影响）。两套坐标系差三件事，
插件替你换算好了：

- 核心的 `rowIndex` 是**显示列表**下标（含分组行 / 展开行这类合成行），而导出会跳掉合成行
- 核心的 `colIndex` 只数**非固定列**（固定列不参与合并），而导出的列序是完整的可见叶子列
- sheet 里顶上还压着 N 行表头

::: warning 跨到没导出的行 / 列上的合并会被丢掉
一个合并块跨过了被跳掉的分组行（或被隐藏的列）时，它在 sheet 坐标里**不再是一个连续矩形**。
这种块会被整块丢掉并在控制台报一句「有 N 个合并区域没能还原」——**不做截断**：截出来的
合并块位置是错的，而错位的合并比没有合并难发现得多。
:::

## 折叠与导出

核心的分组**默认全部折叠**，此时显示列表里只有几行分组标题、一行数据都没有。所以
`includeCollapsed` 默认是 `true`：折叠节点（分组行、树节点）里的行也照样导出。

划的线是：**筛选 / 排序 / 分页是查询，折叠是视图**。前三者改的是「有哪些数据」，导出必须
跟着；折叠只改「现在显示到第几层」，导出不该因此丢数据 —— 否则用户在一张看得见 6 行的表上
点导出，拿到的是个空表。

要严格按屏幕上那几行导就设 `includeCollapsed: false`。

## 多 sheet

```ts
await table.exportXlsx({
  sheets: [
    { name: '明细' },                                        // 当前表格的全部列与行
    { name: '仅金额', columns: ['dept', 'amount'] },          // 只要这几列
    { name: '汇总', rows: summaryRows, merges: false },       // 换一份数据
  ],
});
```

| 字段 | 说明 |
| --- | --- |
| `name` | sheet 名（同样会被清洗与去重） |
| `rows` | 这张 sheet 的行；省略 = 当前表格的行 |
| `columns` | 只要这几列（按列 key，**顺序即列序**）；省略 = 当前的导出列 |
| `freeze` | 覆盖这张 sheet 的冻结设置 |
| `merges` | 这张不要合并（明细要、汇总不要，是常见组合） |

给了 `sheets` 就完全按它出（第一张也来自这里），`sheetName` 被忽略，文件名取第一张的名字。

::: warning 自定义 rows 的 sheet 不带合并
合并坐标是按**显示列表**定义的。换了一份数据之后那套坐标不再对应任何东西，所以这类 sheet
的合并会被跳过（不是 bug，是没有可用的坐标）。
:::

## 合计行写成活公式

```ts
vtXlsx({ liveSummary: true })
```

合计格会变成 `=SUBTOTAL(9, C2:C100)` 而不是一个死数字 —— 收到文件的人筛选或删行之后，
合计自己跟着变。用 `SUBTOTAL` 而不是 `SUM` 正是为了「筛选后只算可见行」，与表格里合计行的
语义一致。

只有核心算出来是**纯数字**的那些格会转成公式（合计行第一格常是「合计」两个字、文本列的
合计格是空串），其余原样写文本。

## PDF 这一档到底做了什么

**本包不生成 PDF 字节。** 它排好一份分页的打印文档，由浏览器的「打印 → 另存为 PDF」出文件。

这是个刻意的取舍，理由只有一条：真写 PDF 字节就必须**内嵌字体**，而中文字体最小的一份也有
4~9 MB。把它打进一个表格插件里，等于让每个客户为「偶尔导一次 PDF」付 9 MB 的包体；不内嵌
则中文全是空白方块 —— 那种 PDF 交出去比没有更糟。

所以这一档卖的是**排版**，而那恰恰是免费版做不到的地方（虚拟滚动的 DOM 里只有一屏行）：

- 分页 + **每页重复表头**（多级分组表头连着 rowspan/colspan 一起重复）
- 页码、标题、页脚备注
- 横向 / A4·A3·letter·legal / 页边距 / 缩放到一页宽
- 一行不会被切成两半

```ts
await table.exportPdf({
  title: '2026 年 8 月对账',
  landscape: true,
  paper: 'A4',
  margin: '12mm',
  footNote: '导出时间 2026-08-31',
});
```

| 选项 | 默认 | 说明 |
| --- | --- | --- |
| `title` | — | 画在第一页顶部，也是打印对话框里的默认文件名 |
| `landscape` | `false` | 横向纸张 |
| `paper` | `'A4'` | `A4` / `A3` / `letter` / `legal` |
| `margin` | `'12mm'` | 页边距，CSS 长度 |
| `pageNumbers` | `true` | 右下角「当前页 / 总页数」 |
| `footNote` | — | 页脚左侧的备注 |
| `selectionOnly` | `false` | 只打选区 |
| `htmlOnly` | `false` | 不唤起打印，把排好的 HTML 返回 |

**要服务端出 PDF 字节**就用 `htmlOnly`，把 HTML 交给服务端的 headless Chrome：

```ts no-check
const html = await table.exportPdf({ htmlOnly: true, title: '月度报表' });
await fetch('/api/render-pdf', { method: 'POST', body: html });
```

定时报表邮件这类场景本来也不该在浏览器里做。

## 纯逻辑层可以单独用

三层都导出了，可以脱离表格（甚至脱离浏览器）用 —— 服务端拼 xlsx 走的就是这条：

```ts no-check
import { buildWorkbook, buildZip, StyleTable, buildSheet } from '@virt-table-pro/xlsx';

const styles = new StyleTable();
const bold = styles.add({ bold: true, fill: 'F1F5F9', border: true });

const parts = buildWorkbook(
  [{ name: '汇总', rows: [[{ v: '部门', s: bold }, { v: '金额', s: bold }], [{ v: '研发' }, { v: 42000 }]] }],
  styles,
);
const bytes = await buildZip(
  parts.map((p) => ({ path: p.path, data: new TextEncoder().encode(p.xml) })),
);
```

| 导出 | 做什么 |
| --- | --- |
| `buildZip` / `crc32` | ZIP 写入器（STORE + `deflate-raw`） |
| `buildWorkbook` / `sheetXml` / `StyleTable` / `SharedStrings` | 一份 sheet 模型 → OOXML 各个 part |
| `buildSheet` / `buildHeaderMatrix` / `translateMerges` | 表头树摊平、合并坐标换算 |
| `buildPrintDocument` | 打印用的分页 HTML（服务端出 PDF 用它） |

## 已知边界

- **分组表尾**（列树 + `showSummary` 的那种多级表尾）不导出。核心那份是渲染时逐格算的，
  没有可读的一维表达；扁平合计行（`footerData`）正常导出。
- **`render` 返回的 DOM 不参与导出**。要让导出与屏幕一致就在列上配 `exportValue` ——
  与核心 `vtExport` 同一份约定。
- **条件格式与图片**不在这一版里。单元格底色可以经 `theme` 与自定义样式做，规则式条件格式
  是另一个包的事。
