`undo` / `redo` 必须是**幂等的「设为某个值」**，不能是「取反 / 再加一次」—— 用户可能反复
撤销重做同一条。

### 行增删

```ts
function removeRow(index: number): void {
  const [removed] = rows.splice(index, 1);
  table.setList(rows);
  table.recordChange({
    label: `删除 ${removed.name}`,
    undo: () => {
      rows.splice(index, 0, removed);
      table.setList(rows);
    },
    redo: () => {
      rows.splice(index, 1);
      table.setList(rows);
    },
  });
}
```

### 多步合成一条

`recordTransaction(label, fn)` 把 `fn` 里发生的**一切**合成一条历史：期间的 `recordChange`
攒起来，期间的状态变更由前后快照的 diff 兜住。撤销一次全退回。

```ts
const targets = rows.slice(0, 50);
const before = targets.map((r) => r.amount);

table.recordTransaction('批量涨价 10% + 按金额排序', () => {
  for (const r of targets) r.amount = Math.round(r.amount * 1.1);
  table.recordChange({
    label: '涨价 50 行',
    undo: () => {
      targets.forEach((r, i) => (r.amount = before[i]));
      table.forceUpdate();
    },
    redo: () => {
      targets.forEach((r) => (r.amount = Math.round(r.amount * 1.1)));
      table.forceUpdate();
    },
  });
  table.sort('amount', 'desc'); // 状态变更也并进同一条
});
```

撤销时的顺序是**先数据、后状态**：手动条目逆序退（后发生的先退），然后一次 `setState`
恢复视图 —— 先把数据摆回原样再恢复筛选，不容易看到「按已被撤销的值筛出来的空表」这种中间态。

嵌套调用只认最外层（内层直接执行 `fn`）。

## 配置项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `limit` | `number` | `50` | 最多保留多少条，超出从最旧的一端淘汰 |
| `autoCapture` | `boolean` | `true` | 是否自动捕获查询状态变更。关掉 = 纯手动模式 |
| `hotkeys` | `'root' \| 'document' \| false` | `'root'` | 快捷键挂在哪一层 |
| `labels` | `Partial<HistoryLabels>` | 中文 | 自动层的标签文案 |
| `onChange` | `(info: HistoryChangeInfo) => void` | — | 历史长度或游标变化时触发 |

```ts
// 英文站点
vtUndo({
  labels: {
    columnWidth: 'Column width',
    columnOrder: 'Column order',
    columnVisible: 'Column visibility',
    sort: 'Sort',
    filter: 'Filter',
    pagination: 'Pagination',
  },
});
```

::: tip 表格状态由外部单向驱动时关掉 autoCapture
Redux / 路由 / URL query 驱动表格状态时，`autoCapture: false` —— 否则撤销会与那份单一数据源打架。
关掉之后只有 `recordChange()` 录进来的才进历史。
:::

### 快捷键

| 组合 | 动作 |
| --- | --- |
| `Cmd/Ctrl + Z` | 撤销 |
| `Shift + Cmd/Ctrl + Z` | 重做 |
| `Ctrl + Y` | 重做（Windows 习惯；mac 上 `Cmd+Y` 是别的功能，不抢） |

| `hotkeys` | 行为 |
| --- | --- |
| `'root'`（默认） | 挂在表格根元素。焦点在表格内才响应，不劫持整页的 `Cmd+Z` |
| `'document'` | 表格是页面主体时更顺手，但会抢走页面上其它编辑器的撤销 |
| `false` | 不绑，只留 API |

**两种情况插件主动让路**（不 preventDefault，交给浏览器/编辑器）：焦点在
`input` / `textarea` / `select` / `contenteditable` 里；以及 `vtCellEditor` 的编辑浮层开着时。
用户在编辑框里按 `Cmd+Z` 想撤的是自己刚敲的字，不是表格的列宽。

## 实例 API

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `undo()` | `boolean` | 撤销一步；没有可撤销的返回 false |
| `redo()` | `boolean` | 重做一步 |
| `canUndo()` / `canRedo()` | `boolean` | |
| `getHistory()` | `HistoryChangeInfo` | 两侧可用性 + 标签，与 `onChange` 收到的一样 |
| `clearHistory()` | `void` | 清空历史。**表格状态不变** |
| `recordChange(input)` | `boolean` | 录一条自定义变更。只记录不执行 |
| `recordTransaction(label, fn)` | `boolean` | 把 `fn` 里的一切合成一条 |

```ts
interface HistoryChangeInfo {
  canUndo: boolean;
  canRedo: boolean;
  /** 两侧都是「离当前最近的排最前」，UI 取 [0] 就是下一步 */
  labels: { undo: string[]; redo: string[] };
}
```

自动层的标签由 diff 出来的类别拼成：`列宽`、`排序`、`排序、筛选`（一次 `setState` 改了多样时）。

## 几件需要知道的事

**撤销之后再产生新变更，被撤销的那一段永久丢弃。** 与编辑器一致；保留分支就得引入撤销树与
选择 UI，对表格是过度设计。

```
entries:  [ A ][ B ][ C ]          全部已应用
undo()  →      ↑                   C 已撤销，redo 能把它推回来
push(D) →  [ A ][ B ][ D ]         C 永久丢弃
```

**不会自己撤销自己。** 回放期间有一道计数闸门：`undo()` 里的 `setState` 同样会敲响
`onColumnsChanged`，不挡住的话撤销动作本身会被记成新历史，按一次 `Cmd+Z` 就在两个状态间反复弹跳。

**历史基线在 `onMounted` 建，不在 `setup`。** 首帧的列树重建会敲一次 `onColumnsChanged`，
那时若已有基线，表格一挂载就会凭空多出一条历史。

**手动条目里的回调抛错不连坐。** 会 `console.error` 一条并继续；游标不回退（半成功状态下退回游标，
下一次 undo 会把同一条重放一遍，那更糟）。

**与 <ProLink to="views">命名视图</ProLink> 一起装是安全的**：`applyView()` 走 `setState`，会被自动层记成
一条历史，所以「切错视图了」按 `Cmd+Z` 就能回来。

**与 <ProLink to="formula/column">计算列</ProLink> 一起装时**，公式列的重算是插件写回 `row[key]`，不进历史 ——
想让它可撤销就把「改源数据」那一步用 `recordTransaction` 包起来。

## 纯逻辑层：撤销栈单独可用

`HistoryStack` 不碰 DOM、不认识表格，可以直接拿去给别的东西做历史：

```ts
import { HistoryStack } from '@virt-table-pro/undo';

const stack = new HistoryStack(20);
stack.push({ label: '改标题', undo: () => {}, redo: () => {} });

stack.canUndo(); // true
const entry = stack.takeUndo(); // 取出并前移游标，**不执行**
entry?.undo(); // 执行由调用方负责（它才知道要不要开闸门）
stack.labels(); // { undo: [...], redo: [...] }
```

快照比较那一层也导出了：`DEFAULT_LABELS`、`HistoryLabels`、`StateChangeKind`。
