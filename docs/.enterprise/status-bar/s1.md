## 配置项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `aggregates` | `StatusAggKind[]` | `['count','sum','avg','min','max']` | 选区聚合显示哪几项，**顺序即展示顺序** |
| `counts` | `StatusCountKind[]` | `['total','filtered','checked']` | 左侧行数统计显示哪几项 |
| `format` | `(value, kind, ctx) => string` | 千分位 | 数字怎么显示，`ctx.columnKeys` 是选区覆盖的列 |
| `items` | `(summary) => StatusBarItem[]` | — | 追加自定义条目，每次刷新调一次 |
| `mount` | `HTMLElement \| () => HTMLElement` | 自动包壳 | 条挂到哪 |
| `copyOnClick` | `boolean` | `true` | 点一项复制它的值 |
| `texts` | `Partial<Record<…, string>>` | 中文 | 文案覆盖 |
| `visible` | `boolean` | `true` | 起手显不显示 |

`aggregates` 可选的项：

| 项 | 是什么 |
| --- | --- |
| `count` | 选中的格子数（含空格） |
| `numericCount` | 其中**能当数字**的格子数 |
| `filled` | 非空格子数 |
| `sum` / `avg` / `min` / `max` | 只算能当数字的那些 |
| `distinct` | 去重后的取值数（按**原始值**算，`1` 与 `'1'` 是两种） |

`counts` 可选的项：`total`（源数据行数）/ `filtered`（筛完剩多少）/ `checked`（勾选了几行）/
`selectedRows`（选区覆盖几行）。后两个**为 0 时不占位置** —— 常态是 0，一直挂着两个「0」是噪音。

## 算不出来就不显示

选中一片文字时 `sum` / `avg` / `min` / `max` **整项消失**，不是显示 `0`，也不是显示「—」：

> 一列文字上的「求和 0」会被读成「这一列加起来是零」。

判断严到把布尔也排除在外，因为 `Number(true) === 1` 会把一列勾选悄悄求和成
「有几个真」—— 那看着像功能，但用户想不到，也没法从数字上看出来。

完整口径（这些**全都不算数字**）：

| 输入 | 结果 | 不这么做会怎样 |
| --- | --- | --- |
| `''` / `null` / `undefined` | 不算 | `Number('')` 是 `0`，空格子会进均值的分母 |
| `true` / `false` | 不算 | 一列勾选被求和成「有几个真」 |
| `'0x10'` / `'Infinity'` | 不算 | 产品编号里的 `0x10` 被算成 16 |
| `'12abc'` / `'1.2.3'` | 不算 | 半个数字被当成数字 |
| `NaN` / `Infinity` | 不算 | 进了 `sum` 会把整列结果污染成 `NaN` |
| `0` | **算** | 用 `\|\|` 兜底的写法会把它当空 |
| `'1,234'` / `'¥1,234'` / `'12.5%'` | **算**（1234 / 1234 / 12.5） | 从 CSV 导进来的数字常带这些 |
| `Date` | **算**（时间戳） | 对日期列取 min/max 是「最早 / 最晚」，有意义 |

百分数**不除 100**：用户看到的是 `12.5%`，两个 12.5% 求和该得 25 而不是 0.25。

## 金额求和不会飘出浮点尾巴

一千行两位小数朴素累加会得到 `1234.5600000000002`。这个数是用户拿去核对账的，
所以求和走 Kahan 补偿求和（多一次减法，代价可忽略）。

## 「总行数」不跟着筛选变

`total` 是**源数据**行数，`filtered` 才是筛完剩下的。这一条曾经是个 bug：状态栏原来读
`options.list.length`，而核心会把 `options.list` **改写成展示列表**交给虚拟滚动 ——
筛掉一半之后显示的是「总行数 2 / 当前 2」，两个数字一样，一点都不显眼。

核心为此补了公开的 `getSourceRowCount()`（2026-09-01）。

## 功能列不进聚合

序号、勾选、单选、拖拽把手这些列即使被选区横跨也不算 —— 判据与「复制选区」「导出选区」
是同一套（`getSelectableColumnIndexes()`）。把行号加进求和是完全静默的错误。

## 点一项复制的是**未格式化**的数字

条上显示 `3,500`，复制出去是 `3500`。复制它的人是要贴到别处继续算的，千分位与货币符号
贴过去反而要手工删。

## 自定义条目

`items` 每次刷新调一次，拿到当前汇总。返回 `value` 为空字符串的项**不显示**：

```ts
vtStatusBar({
  items: (s) => [
    { key: 'rate', label: '选中占比', value: s.filtered ? `${((s.selectedRows / s.filtered) * 100).toFixed(1)}%` : '' },
    { key: 'cols', label: '跨列', value: s.columnKeys.length > 1 ? String(s.columnKeys.length) : '', side: 'left' },
  ],
})
```

按列决定单位用 `format`：

```ts
const CNY = new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' });

vtStatusBar({
  // 选区只覆盖一列时才敢加单位 —— 跨列时不同列的单位不一样
  format: (v, kind, { columnKeys }) =>
    columnKeys.length === 1 && columnKeys[0] === 'amount' && kind !== 'count'
      ? CNY.format(v)
      : v.toLocaleString(),
})
```

::: warning 别拼 `` `¥${v}` ``
负数上它会拼出 `¥-87,355`，而中文的正确写法是 `-¥87,355`（负号在货币记号**之前**）。
金额列一有负数，「最小」那一项就会露出来。`Intl.NumberFormat` 的 `style: 'currency'`
按各地区规则摆符号，自己拼永远会漏掉某个地区。

`kind !== 'count'` 那一句同理：给「选中 100 个格子」标上货币符号是另一种同类错误。
:::

## 实例 API

| 方法 | 作用 |
| --- | --- |
| `getStatusBarSummary()` | 拿当前汇总（**不依赖 DOM**，可以拿去自己渲染） |
| `refreshStatusBar()` | 手动刷一次（外部改了数据但没走 `setList`） |
| `showStatusBar(visible?)` | 显隐；不传参则切换 |
| `isStatusBarVisible()` | 现在显示着吗 |

`getStatusBarSummary()` 的形状：

```ts no-check
{
  selection: { count, numericCount, filled, sum, avg, min, max, distinct },
  range: { startRow, startCol, endRow, endCol } | null,
  columnKeys: string[],      // 选区覆盖了哪些列
  total, filtered, checked, selectedRows,
}
```

无选区时 `selection` 里的数值项是 `null` 而不是 `0` —— 「没得算」和「算出来是 0」得能分开。

## 条挂在哪

默认在 `.vt-root` **外面**包一层纵向 flex，条排在表格下方。塞进 `.vt-root` 里会被虚拟滚动的
几何计算算进内容高度。

已经装了 `vtToolbar` 时**复用它那层壳**，不再套一层（套两层的实测表现是表格底下空出一条）。
想自己决定位置就给 `mount`：

```ts
vtStatusBar({ mount: () => document.querySelector('#my-footer')! })
```

::: warning 自定义槽要能拿到 token
条上的颜色全走 `--vt-*`。插件会给槽自动加 `.vt-fb`（核心给「表格之外的 DOM」准备的变量载体），
但那个槽得在页面里真实存在 —— 否则条不会渲染，也不报错。
:::

## 聚合算术能单独用

同一套口径在别处复用（一个卡片、一段服务端汇总）：

```ts
import { aggregate, toNumber, formatNumber } from '@virt-table-pro/status-bar';

aggregate([10, '', null, 20]); // { sum: 30, avg: 15, numericCount: 2, filled: 2, … }
toNumber('¥1,234');            // 1234
formatNumber(1 / 3, 'avg');    // '0.3333'
```

刻意公开的原因是**口径一致**：自己再写一份，迟早会在「空串算不算 0」这种地方和状态栏对不上。

## 没装 `vtCellSelection` 会怎样

条照常出现，只有左侧的行数统计，并 `console.warn` 一次。

没写成 `requires: ['vtCellSelection']`（那会让整个插件被跳过）—— 只有行数统计也是有用的，
不该因为少装一个插件就连行数都没了。
