密钥、产品名、以及**未授权时到底会发生什么**。API 细节在
<ProLink to="license">许可与角标</ProLink>，这一页只讲模型。

## 只 warn，绝不降级

校验失败时**只**输出一行 `console.warn` + 界面右下角一枚角标。不抛错、不禁用功能、
不静默改行为。

| | |
| --- | --- |
| 功能 | **完全正常** —— 不禁用、不限行数、不往数据里加水印 |
| console | 每个未授权产品 **warn 一次**（不刷屏），带原因与联系方式 |
| 界面 | 表格根元素右下角一枚 `.vtp-license-badge`，`aria-hidden`、不吃指针事件、不进 tab 序 |

理由有两条，缺一条这个选择都不成立：

1. **约束力来自企业合规**（采购、审计、法务），不来自客户端代码。
2. **能炸掉生产表格的校验会把人逼去绕过它**。一个「许可过期 → 表格白屏」的设计，第一次出事
   之后客户学到的不是续费，而是把校验注释掉。

AG Grid 走的也是这条轻校验路线。

::: tip 这条对你意味着什么
可以放心把付费插件装进生产环境：许可问题最坏的后果是控制台一行告警和一枚角标，
**不存在**「许可服务挂了导致表格崩」这种故障模式 —— 校验完全在本地，不发任何网络请求。
:::

## 产品名 = 包名后半段

密钥 payload 里的 `products` 是一串产品名，与包名后半段一致：

```json
{ "sub": "ACME Inc.", "products": ["views", "undo", "formula"], "exp": "2027-01-01" }
```

`'*'` 表示全部。每个付费插件启动时检查自己那一个产品名，所以「买了哪些」是**逐插件**生效的，
不是一刀切 —— 一把密钥可以覆盖多个产品，应用里只设一次。

各插件页顶部的状态条上都写着该插件的产品名。

## 开发域名一律放过

`localhost` / `127.0.0.1` / `[::1]` / `*.localhost` / `*.local` / `*.test` 与空 host 不做域名校验。

你拿到的密钥绑的是生产域名，而团队 90% 的时间在 localhost 上开发 —— 每次 dev server 都
warn 一遍域名不匹配，只会把人逼去找绕过校验的办法。同理，`*.example.com` 这种通配符
**同时覆盖裸域** `example.com`。
