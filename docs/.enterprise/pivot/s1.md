## 配置项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `rows` | `string[]` | — | 行维度字段，**顺序即层级** |
| `columns` | `string[]` | — | 列维度字段（交叉分析的横轴），顺序即表头层级 |
| `values` | `PivotValue[]` | — | 值字段与聚合方式，见下 |
| `showSubtotals` | `boolean` | `true` | 行维度中间层出小计行。`false` 时变成平表，见「两种形式」 |
| `showGrandTotal` | `boolean` | `true` | 最后加一行总计 |
| `showColumnTotal` | `boolean` | `true` | 有列维度时最右边再来一组总计列 |
| `filter` | `(row) => boolean` | — | **只统计满足条件的明细行**，见「它在管线里的位置」 |
| `sortDimensions` | `'asc' \| 'desc' \| false` | `'asc'` | 维度取值的排序。数字型取值按**数值**排 |
| `dimWidth` / `valueWidth` | `number` | `200` / `120` | 维度列宽 / 值列宽 |
| `dimTitle` | `string` | 维度字段名连起来 | 行维度列的标题 |
| `totalTitle` | `string` | `'总计'` | 总计行与总计列的文案 |
| `showCount` | `boolean` | `true` | 维度格右侧显示「这个小计覆盖了多少条明细」的徽标 |
| `formatValue` | `(value, v) => string` | 千分位 | 值的显示格式化 |
| `renderValue` | `(v) => render` | — | 值列的自定义渲染（色阶、数据条）。与 `formatValue` 二选一，这个赢 |

`rows` 与 `values` **都为空时插件完全让路** —— 表格就是原来那张表，一行数据都不动。
所以「先装上、之后再按需打开」是安全的。

### 值字段

```ts no-check
values: [
  { field: 'amount', agg: 'sum' },
  { field: 'amount', agg: 'avg', title: '客单价' },
  { field: 'id', agg: 'count', title: '笔数' },
  { field: 'customer', agg: 'countDistinct', title: '客户数' },
  { field: 'amount', agg: (rows) => rows.filter((r) => r.amount > 1000).length },
]
```

| `agg` | 算什么 |
| --- | --- |
| `sum` / `avg` / `min` / `max` | 只看得出数的那些值。数字字符串（后端给的 decimal）与布尔（当 1/0）都算 |
| `count` | **行数**，含该字段为空的行 |
| `countDistinct` | 该字段的去重取值数 |
| 函数 | 拿到这一格覆盖的整桶明细行，返回任何东西 |

::: tip 一个数字都没有时是空，不是 0
`sum` / `avg` / `min` / `max` 在桶里找不到任何数字时返回 `null`，显示成空格。
「这个季度没有销售」与「这个季度卖了 0 元」在报表里是两件事，不该长得一样。
:::

## 实例 API

```ts
table.setPivotConfig({ rows: ['dept'], values: [{ field: 'amount', agg: 'avg' }] });
table.setPivotConfig(null);   // 关掉透视，行与列都退回明细视图
table.getPivotConfig();       // 当前配置的副本，关着时 null
table.getPivotResult();       // { rows, colTree, colPaths, sourceCount }，关着时 null
```

`setPivotConfig` 是**整体替换**而不是合并（与 `setState` / `setGroupConfig` 同语义）。
要改一处：

```ts no-check
table.setPivotConfig({ ...table.getPivotConfig()!, rows: ['region', 'city'] });
```

`getPivotResult()` 给的是原始结果，用来「把透视结果导出成 xlsx」或者「把列维度的取值填进
自己的下拉」。

## 它在管线里的位置（**这一节一定要读**）

核心的数据管线是这样的，透视挂在**最前面**：

```
明细 → [透视] → 筛选 → 排序 → 分页 → 合计 → 结构展开 → 提交
```

为什么在最前面：这个插件**同时会换掉列**，而筛选与排序的谓词是照**当前列**建的 ——
换列之后再筛明细行，就是拿透视列的谓词去问明细行，那没有意义。

于是有一个必须如实知道的后果：

::: warning 列头筛选与排序作用在透视结果上，不是明细上
- 点「金额 求和」那一列排序 → 按聚合值排（**这正是透视表最常用的动作**）
- 列头筛选「大区 = 华东」→ 筛的是透视出来的那一行
- **想筛明细**（「只统计已完成的订单」）→ 用 `filter` 选项，或者先筛好数组再 `setList()`
:::

```ts no-check
vtPivot({
  rows: ['region'],
  values: [{ field: 'amount', agg: 'sum' }],
  // 只统计已完成的订单。放这里也更快：先筛再聚合，少算的那部分完全不进循环
  filter: (o) => o.status === 'done',
});
```

换来的是三件事白拿核心：**值列可排序**、分页切的是透视行、`showSummary` 的合计行统计的是
透视值。

## 小计的算法

小计行的每个格都是**对该桶内全部明细重新跑一次聚合**，不是把子行的值加起来。

对 `sum` 两者一样，对 `avg` / `min` / `max` / `countDistinct` **不一样**：

```
华东 · 市场   300        ← 一条明细
华东 · 研发   150        ← 两条明细 100 / 200 的平均
华东（小计）  200        ← 三条明细 100/200/300 的平均 ✔
              225        ← （300 + 150) / 2 ✘ 按子行平均，错
```

「各部门平均值的平均」不是「大区的平均」。按子行相加是报表里最常见的错，这里没有犯。

同理，表尾合计（使用方开了 `showSummary` 才画）**只给可加的聚合**上：只有 `sum` 与
`count` 的值列带 `summary`，`avg` / `min` / `max` / `countDistinct` 与自定义聚合不带 ——
给不可加的聚合摆一个合计格，比留空更糟，它是个看起来很正经的错数字。

## 两种形式

| | `showSubtotals: true`（默认，压缩形式） | `showSubtotals: false`（表格形式） |
| --- | --- | --- |
| 行 | 一棵树：每层一个小计行，`children` 是下一层 | 平表：只有最深一层的组合 |
| 行维度列 | **一列**树形列，层级靠缩进 | **每个维度一列** |
| 折叠展开 | 有 | 没有（本来就没有层级） |

Excel 管这两种叫「压缩形式」与「表格形式」。表格形式下之所以要每个维度各占一列：
一列树形列只显示得了**一层**的取值，`rows: ['region','dept']` 会变成「只看得见部门、
看不见大区」。

## 静态合并会被自动收起

表上配了 `options.merges` 的话，开启透视时插件会**存一份并清空**，关掉透视时原样还回去。

原因：合并坐标是按**显示行号**定义的，而透视把行集整个换掉了 —— 那份坐标指向的行已经
不存在。不清的话表上会浮着一批位置毫无意义的合并格。「经典案例 · 电子表格」那张表有
2.7 万个合并区（按十万行明细算的），透视出 11 行汇总时全是错的。

列上的 `mergeKey` 自动合并不用管：那是列配置，换列时自然就没了。

## 折叠展开与性能

折叠展开完全是核心的：`toggleFold(rowKey)` / `expandAll()` / `collapseAll()` 照常用，
行 key 就是维度取值路径（`'华东'`、`'华东<分隔符>研发'`）。

变换钩子**每次数据重建都会被调**（折叠一下、排一次序都算），所以聚合结果按
「**源数组引用 + 配置版本号**」记了缓存：折叠不换源数组也不改配置 → 命中缓存，
一次聚合都不跑。换数据（`setList`）或 `setPivotConfig()` 才会重算。

## 已知边界

- **没有配置面板 UI**。`setPivotConfig()` 是命令式入口，界面（拖字段到行区/列区/值区）
  由使用方自己做 —— 一个 `<select>` 加一个按钮就能接上。面板是下一期。
- **没有明细下钻**。双击一个聚合格看它由哪些明细构成，需要在聚合时保留每格的源行引用
  （十万行时内存不小），下一期做成可关的选项。
- **表格的 `itemKey` 不能与维度字段同名**。行 key 会写到 `itemKey` 那个字段上，
  撞了会盖掉维度取值 —— 会有一条 warn 说明。给表格用 `id` 这类中性 key 即可。
- **服务端模式（`manualSorting` / `manualFiltering`）下透视仍在本地算**。它吃的是
  `list` 里的明细，服务端只给一页数据时聚合出来的就只是那一页。

## 纯逻辑层可以单独用

两层都导出了，能脱离表格（甚至脱离浏览器）用 —— 服务端算透视走的就是这条：

```ts no-check
import { pivot, buildPivotColumns, cellKey } from '@virt-table-pro/pivot';

const result = pivot(orders, {
  rows: ['region'],
  columns: ['quarter'],
  values: [{ field: 'amount', agg: 'sum' }],
});

result.rows[0][cellKey(['Q1'], 'amount')]; // 华东 Q1 的金额
result.colTree;                            // 列维度取值树
```

| 导出 | 做什么 |
| --- | --- |
| `pivot` / `aggregate` | 聚合本体与单格聚合 |
| `buildColTree` / `colLeafPaths` / `cellKey` | 列维度取值树与交叉格的 key |
| `buildPivotColumns` / `renderDimCell` | 结果 → `VirtTableColumn[]`（自己拼一张普通表也行） |

`cellKey()` 是拼交叉格 key 的**唯一正路** —— 分隔符是实现细节，手写会在维度取值本身
含 `/` 或 `-` 时撞车。
