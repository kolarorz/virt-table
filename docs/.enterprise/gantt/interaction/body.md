拖条改期之后谁写回数据、里程碑怎么点出来、命令式 API。

## 写回约定（重要）

**插件不写回行数据。** 行数据是使用方的，往里塞值会污染序列化 / 深拷贝 / diff
（与核心 `renderEditor` 的取舍一致）。`onChange` 给出新旧值，写回是你的事：

```ts
vtGantt<Task>({
  start: 'start',
  end: 'end',
  onChange: (e) => {
    const task = findTask(tasks, e.rowKey);
    if (!task) return;
    task.start = toISODate(e.start); // 按你自己的字段格式
    task.end = toISODate(e.end);
    task.progress = e.progress;
    table.refreshGantt(); // 清汇总条记忆表 + 重渲染表格与条形层
  },
});
```

`refreshGantt()` 里带了 `forceUpdate()`，所以左边那几列（开始 / 结束 / 进度）的单元格
会一起刷新。早先它只重画条形层，于是拖完条时间轴对了、左边单元格还是老数字 ——
那是个陷阱，已经修掉。

没有写回时，条会在松手后**弹回原位** —— 那是对的：界面必须与数据一致，
否则用户以为改成功了而后端从没收到。

`GanttChange` 的字段：

```ts no-check
{
  kind: 'move' | 'resize-start' | 'resize-end' | 'progress',
  rowKey, row, rowIndex,
  start, end, progress,                       // 新值
  prev: { start, end, progress },             // 旧值，便于做撤销记录
}
```

配 `@virt-table-pro/undo` 时在这里调一次 `recordChange({ label, undo, redo })` 即可。

## 里程碑

**一个里程碑 = 一条贯穿所有行的竖线。** 与行数据无关，不占行 —— 它是时间轴上的注记
（发布日、评审会、合同截止），不是任务。

```ts
vtGantt({
  start: 'start',
  end: 'end',
  markers: [
    { date: '2026-09-01', label: 'v2.0 发布' },
    { date: '2026-09-15', label: '合同截止', className: 'my-hard' },  // 逐条配色
  ],
  editable: { marker: true },              // 允许从表头点出来
  onMarkerCreate: (m) => save(m),          // 插件已经加进去了，这里只是让你持久化
})
table.setGanttMarkers(list);
table.getGanttMarkers();
```

`GanttMarker` 四个字段：`date`（必填）、`label`、`color`、`className`。

- **名字默认不显示，hover 竖线才出来。** 一堆常驻标签会把时间轴糊住，密集时还互相压字，
  而线本身已经足够表达「这里有个节点」。`label` 同时挂在 `title` 上（无障碍与长按提示）
- 竖线只有 2px，指针几乎碰不到，所以元素做成 **9px 的透明命中区** + 居中的 `::before` 画线。
  代价是那 9px 宽的一列挡住了下方单元格的点击；条形层在 DOM 里排在标记之后，
  所以**条压在竖线上时命中的是条**，拖条不受影响（有实测）
- 落在时间轴范围之外的标记**不画**（夹到边缘会骗人：看起来像发生在第一天）
- 竖线画在**它那一天的正中**，不是那一天的 0 点。0 点就是格子的左边界，线压在两天中间 ——
  「6 号」与「5 号和 6 号之间」看起来一模一样，日视图下尤其别扭；而 `date` 语义上是**一个日期**
  （发布日、评审会），不是一个时刻。

  做法是**把时间量化到天再取中点**，不是「加半个桶宽」：加半个桶在日视图下等价，但月/季视图下
  会把 1 月 15 号的标记推到 2 月初；而只对「正好落在桶起点」的标记做偏移会造成跳变
  （0 点居中、0:01 贴边）。量化到天是安全的 —— `GanttZoom` 最细就是日。
  中点用 `(dayStart + nextDayStart) / 2` 算而不是加 12 小时：夏令时那天只有 23 小时
- 标签贴在**可见数据区的上缘**（用核心发布的 `--vt-body-view-t` 让开表头），
  并抬到条之上（`z-index: 1`）—— 静态层在 DOM 里排前面，否则会被条盖住
- 标记归**静态层**：只随时间轴几何变化重建，所以和条一样在横滚时零 JS

### 「今天」的标识：日期上的蓝色圆底

表头上今天那一格，**日期本身套一个蓝色圆底**（与今天线同一支蓝）。日历里通用的写法，
一眼就懂 —— 早先是在竖线顶端挂一枚写着 `T` 的小牌，那个得先有人教你它是什么意思。

实现走核心的 `renderHeader`（列上的声明式钩子）而不是渲染完去改 DOM：表头会随列窗口
重建，改 DOM 的写法每次重建都要补一遍。注意**必须返回元素**，核心对字符串走
`textContent`、不解析 HTML。

粗粒度（周/月/季）下套住的是**包含今天的那个桶**，圆底靠 `min-width` + 左右内边距
自然摊成胶囊，不必为两种情况写两套。

`showToday: false` 把竖线与圆底一起关掉。

### 日期格上的旗标

竖线的顶端伸进**它那一格日期表头**里，接上一枚 15px 的小旗子。**旗标只留给里程碑** ——
小旗子自解释「这里有个节点」。

- 竖直方向：`top` = 表头高度 − 旗标边长（`--vt-body-view-t` 是核心发布的表头高度），
  于是牌子的**底边正好压在可见数据区的上缘**，与竖线的顶端相接 —— 看起来是一根从表头
  插下去的旗杆。左下角刻意不倒圆角，否则那里会露出一个缺口
- 水平方向：**左缘与竖线对齐，不做任何偏移**。竖线那 9px 的命中区是靠自己的
  `margin-left: -4px` 抵掉的，旗标这边再 `+4px` 就会比线右 4px（浮在表头上方时看不出来，
  一旦与线相接就是一道明显的错位，实测量到过）。所以线居中到日期格中间之后，旗标也跟着走

（早先是贴在**整个表头的顶端**，那会跑到年月那一层去：离自己的日期格隔着一整行，
和线也是断开的。）

靠**形状**而不是颜色区分类型 —— 两条线挨得近、或者使用方改了主题色时，颜色就承载不了
类型信息了（实测「今天和里程碑看不出区别」正是这么来的）。旗标的名字走原生 `title`。

旗标**不在覆盖层里**，而是 `.vt-client` 的直接子节点：覆盖层自己有 `z-index: 3`，
它就是一个**层叠上下文** —— 里面写多大的 z-index 都出不去，永远盖不过表头（10）。
（这一条实测踩过：旗标写了 `z-index: 12` 却一个都看不见。）

它仍然在滚动容器内，所以横滚照旧由合成器平移；代价是会滑到冻结列后面而又比冻结列高，
那一段按 `scrollLeft` 隐掉 —— 这是横滚时唯一还在跑的 JS，量级是「里程碑个数」次
`style.visibility` 赋值（通常个位数）。

### 「今天」就是一条内置里程碑

`showToday`（默认 true）渲染的是同一套东西，只多一个 `--today` 修饰类换配色，
所以它同样是 hover 才显名、同样有加宽的命中区。

配色用**蓝色**而不是红色：红色在项目管理界面里已经被「有风险 / 延期」占掉了语义，
一条常驻的红线会让人以为整张表都在告警。线本身半透明（0.75），压在条上时条还看得见。
旗标是个方牌（`T`），不做旗子的斜角。

### 一天一条，颜色从预设里挑

**同一天只能有一条里程碑。** 两条同一天的会画在同一个像素上，只有 hover 才分得出 ——
那不是信息，是重影。所以插件在三个入口上统一归一（`markers` 初始值、`setGanttMarkers()`、
界面上新建），**重复日期以后来的为准**；判重的键是「那一天的 0 点」，同一天不同时刻算同一天。

颜色走 `GanttMarker.color`，竖线 / 旗标 / hover 标签共用（内部就是把
`--vtp-gantt-marker-color` 写在那一条的元素上，所以逐条配色只需要一处）。

新建与编辑的浮层里给的是**一排预设色**（`markerColors`，默认紫 / 蓝 / 绿 / 橙 / 红 / 灰），
不是取色器：里程碑的颜色是**分类**用的（发布 / 评审 / 冻结），不是审美选择 ——
六个一眼能分开的色够用，而任意取色只会让同一张图上出现十几种半斤八两的紫。
第一个是默认色，与 `--vtp-gantt-marker-color` 的默认值一致。

### 从表头点出里程碑

`editable.marker: true` 之后：hover 时间轴表头的某个日期 → 出现一个小图标 →

**hover 出来的 `+` 只有 18px 见方，所以整格也是入口**：直接点某个日期格 —— 那天没有里程碑就新增、已经有就进编辑（与点旗标同一条路）。早先只有那个小按钮能点，指针稍飘一点就落在格子上、什么都不发生，用户的结论是「点了没反应」。
点它弹出输入框 → 输名字 → **浮层消失即新增**（点浮层外面、按 Enter、点确定都算确认；
Esc 取消；名字留空也算新增，就是一条无名竖线）。

实现上是**一个浮动按钮**跟着 hover 走，而不是给每个日期格塞一个 —— 时间轴动辄几百列。

⚠️ 按钮浮在表头**上面**，但 DOM 里挂的是 `.vt-root`、**不是表头的后代** —— 于是指针从日期格
挪到按钮上的那一刻，表头会收到 `pointerleave`。照单收起的话按钮当场消失，那一下点击落到
底下的表头格上，**什么都不会发生**：这正是「新增里程碑点了没反应」的全部原因
（CDP 实测：hover 时按钮出现在 `(1156,183,18,18)`，指针移上去之后 `display: none`）。

所以离开表头时要先看**去了哪儿**：去按钮或输入浮层就不算离开；从按钮回到表头也不收起
（交给表头的 `pointerover` 接着管）。`gantt.dom.test.ts` 里四条用例守着这个来回。

与行数据不同，标记**是插件自己的状态**，所以这里插件会先把它加进 `markers`，
`onMarkerCreate` / `onMarkersChange` 只是让你有机会持久化。

### 改已有的那条：点它的旗标

一天只允许一条，所以「在已有里程碑的那天再点一次表头的 `+`」没有意义 ——
那一天 hover **不再出 `+`**，改成点**它自己的旗标**（`editable.marker` 下旗标带
`cursor: pointer` 与 `title`）：同一个浮层，进来时带着原名字与原颜色，改完确定即生效。

编辑态里多一颗**删除**。这个面板是这些标记**唯一**的管理入口 —— 它们不在行数据里，
界面上除了那条线什么都没有，只能改不能删的话，点错一天就再也收不回来了。

编辑时**保留使用方原来的 `date` 写法**（`'2026-08-19'` 就还是那个字符串），不换成归一后的
时间戳：指的是同一天，而把别人的数据格式悄悄改掉，下一次 diff / 序列化就对不上了。

## 在空白行上点出工期

```ts
vtGantt({
  start: 'start',
  end: 'end',
  editable: { create: true },
  // 点一下默认排几个桶，默认 1 —— 日视图下就是**一天**。
  // 排一天再拖两端改工期，比默认给一段猜出来的工期让人删掉更顺
  // createSpan: 1,
  onCreate: (e) => {
    // 与 onChange 同样的约定：插件只给日期，写回是你的事
    row.start = toISODate(e.start);
    row.end = toISODate(e.end);
    table.refreshGantt();
  },
})
```

只对**当前没有条**的行生效（已有条的行上点击是 `onBarClick`，而且那一下会被条自己吃掉）。

hover 到这样的行的时间轴格上时，格子里会出现一个虚线框的 `+`，提示「这里可以排期」。
同样是一个浮动元素跟着 hover 走（一屏几百个格子，不能每格一个），
它必须 `pointer-events: none` —— 提示自己把要提示的操作挡掉就成了笑话。

### 时间轴格不进激活态

那圈蓝色描边在时间轴上是纯噪音 —— 那里没有值可选，用户点它的意图是「在这排一段工期」。

描边有**两个**来源，都要压住：

1. 核心的 `highlightSelectCell`；
2. **`vtCellEditor`** —— 它点一下就 `setActiveCell`，**且不管那一列有没有 `renderEditor`**
   （它的注释写得很清楚：只标可编辑格会让描边赖在上一格不动）。所以时间轴格即使完全
   不可编辑，点它也会亮一圈蓝框。早先只判 `highlightSelectCell`，而实际场景里没开那个
   选项，于是那段抑制形同不存在。

插件在 `click` / `dblclick` 上把它撤掉，监听挂在 **`ctx.rootEl`** 而不是 `tbodyEl`：
`vtCellEditor` 挂在 tbodyEl 上，冒泡到 rootEl 一定在它之后 —— 与两个插件谁先声明无关
（它们都没有 `requires`，安装顺序就是声明顺序，指望顺序是靠不住的）。业务列照常。

实现上不需要任何几何换算：委托在 `tbodyEl` 上，靠 `td` 的 `data-col-key` 反推是第几个桶
（落点由坐标反算：x → 第几个桶、y → 第几行，见 `hitTest()`）。

`endInclusive` 时回传的 `end` 会按同一约定换算回去。

## 拖拽换序

```ts
// editable.reorder 打开后：条上下拖 = 换序，条左右拖 = 改期；任务列上下拖也能换序。
// 变更从表格的 onRowOrderChange 出来 —— 换序由核心的 moveRow() 落地，
// 插件不再另给一个 onReorder（同一件事两个回调，只会让人不知道该听哪个）
new VirtTable<Task>(el, {
  list: tasks,
  columns: taskColumns,
  itemKey: 'id',
  estimatedSize: 40,
  onRowOrderChange: (list) => save(list),
  plugins: [vtGantt<Task>({ start: 'start', end: 'end', editable: { reorder: true } })],
});
```

**按住甘特条上下拖**就是换序，左右拖仍然是改期；左侧任务列上按住整行上下拖也可以。
落点画一条横线：

```
┌──────────┬───────────────────────────┐
│ 设计     │      ████████  ←→ 改期     │
│ 开发     │            ██████         │
├──────────┴───────────────────────────┤ ← 落点提示线（跨全宽）
│ 评审 ⇕拖 │        ██⇕██  ↕ 换序      │
└──────────┴───────────────────────────┘
  ↑ 任务列这侧上下拖也能换序
```

几条刻意的取舍：

- **条上用方向区分意图。** 同一个条既要能改期又要能换序，判据是**越过 4px 阈值那一刻
  两轴位移谁大**：横向主导 → 改期，纵向主导 → 换序。这与核心 `startDrag({ axis })` 和
  `InputController` 的轴锁是同一套启发式，三处的判定不会互相矛盾。阈值前**什么都不预览**
  （条不动、提示线不画），所以不会出现「先跳一下再改主意」。
- **两端手柄与进度手柄不参与换序。** 那三个手势的语义都是「改这一条的长度 / 进度」，
  天生是横向的，在它们上面纵向拖去换行序只会让人误触。
- **一个指针只由一套状态机管。** 方向判明后条那边就地收摊（释放指针捕获），整个手势交给
  换序模块 —— 两套状态机同时盯着同一个指针，光是「谁该在 pointerup 时提交」就说不清。
  交接失败（开关没开、当前状态不允许重排）则回落成改期，行为与没有换序功能时完全一致。
- **任务列那侧也留了入口。** 任务列被**收起**（`panelToggle`）时它自然没了，条那个还在。
- **提示线跨「任务列 + 整条时间轴」**，宽度由 `getColumnRange()` 现算成内容坐标。
  核心 `vtRowDrag` 的那条线写死 `width: 100%`，而绝对定位的百分比按容器**未滚动时的
  padding 盒**解析（= 可视宽而非内容宽）——在普通表格里够用，在甘特这种内容远宽于视口的
  表上一横滚就缺一截。
- **落点若等于原位**（自己身上、自己的上/下边界）**不画线**。画了线又什么都不发生，
  看着就是坏了。
- **三样视觉线索一起给**：跟随光标的 **ghost**（显示 `barLabel`，没给就取第一个业务列的值）、
  源**条**降到 45% 透明 + 虚线描边、源**行**叠一层 12% 主色底。加上落点提示线与 grabbing 光标，
  「你拖的是哪一个 / 会落到哪里」两件事都不用猜。
- **源行的 class 是每帧幂等重刷的，不是挂上去不管。** 行 DOM 属核心且会被**行 DOM 池回收**：
  挂一次就不管的话，拖拽中一旦（自动）滚动，class 就粘到复用后的另一行上，表现是「随便哪一行
  忽然变色」。插件的做法是把「现在拖的是哪一行」记成一个 key，随 `sync()`
  （`onRendered` / `onScroll`）**全量 toggle** 一遍 —— 回收多少次都对。
  `gantt.dom.test.ts` 里有一条用例专门在拖拽中触发滚动 + 换整份数据，断言标记仍然只在源行上。
- **源行的底色用 `background-image` 叠加，不动 `background-color`。** 冻结列的 `td` 靠自己的
  不透明底色遮住从下面滚过去的条 —— 把底色换成半透明的话，横滚时条会从任务名底下透出来。
- **拖拽中整表的 hover 态一律不亮。** 拖着一行从别人身上经过时，本来会一路点亮：核心的行
  hover 底色、被经过的条冒出来的两端手柄与进度手柄、里程碑的名字、空白行那个 `+`、以及往上
  拖过表头时的 `th:hover`。它们都是「这里可以点」的邀请，而此刻唯一有意义的邀请是**落点提示线**。
  做法是给表体 / 表头 / 条 / 标记 / 旗标加 `pointer-events: none`（`.vtp-gantt-reordering`
  这个 class 期间），而不是逐条覆盖那些 `:hover` 规则 —— 一条规则管住核心的、本插件的、
  以及将来新加的所有 hover 效果。**这么关是安全的**：落点是拿指针 Y 去撞
  `getRenderedRowRects()` 算的（不依赖 hit-test），拖拽事件收在 `document` 上（不受影响）。
- **源条留在原位、不跟着光标走。** 条的位置每帧由 `syncBars()` 按行矩形算出来，让它跟手就得在
  每帧同步里加一条「这一条例外」的分支；ghost 已经把「你正拖着的是这个」表达清楚了。
- **按下时不拦事件**，只有真的越过 4px 阈值才接管，且要求**纵向主导**（横滑让回给横滚）。
  这一条是为了不打断 `vtCellEditor` —— 它默认 `trigger: 'click'`、监听挂在同一个
  `tbodyEl` 上，核心 `vtRowDrag` 的 `wholeRow` 分支在 pointerdown 上直接
  `preventDefault + stopPropagation`，装上就点不开编辑器了。拖拽真的发生时，落定那一下
  click 会被吞掉（否则拖完一松手就弹编辑器）。
- 拖到容器上/下边缘会**自动纵滚**（走 `scrollByY()` —— 核心的 `overflow-y` 是 hidden，
  写 `scrollTop` 一动不动），滚动的每一帧都会重算落点。
- 拖拽中行因为**别的**原因动了（滚轮、上面那个自动纵滚、数据变化）时落点也会重算 ——
  否则线停在原处，而松手落到的是另一行。
- **暂无键盘等价操作**（核心 `vtRowDrag` 也没有）。需要无障碍的换序入口时，请在业务侧接
  「上移 / 下移」按钮并自己改数据顺序 —— 那条路不经过本插件。

### 限制：只在扁平且未排序 / 未筛选时可用

判定直接用核心的 `canReorderRows()`：**排序、筛选、树形列、分组、自动合并**下一律为 false。
那些情况里「视图顺序」与「原始数据顺序」不是一回事，拖出来的结果无法预期。
此时手势**不启动**（不画提示线比「画了线但松手没反应」诚实），并 `console.warn` 一次说明原因。

**这是有意收住的范围，不是遗漏。** 换序**只做扁平**：树形 / 分组内的换序要绕开核心
`moveRow`（它对 `groupConfig` 与树形列是硬拒），得由插件自己算新顺序、`setList()` 回灌、
再自备一套回调，还要处理整棵子树搬迁与展开态保持。那一档排在**先支持表格的属性拖拽**之后
再规划 —— 顺序定了才动工，免得两套「拖拽改结构」的交互各长一套心智。

demo 里可以直接看到这条边界：切「扁平」能拖，切回「分组 / 树形」拖不动，
侧边信息框第二行会写明当前形态能不能换序。

> **不要同时装核心的 `vtRowDrag`。** 两套手势会互相抢，还会画出两条提示线。
> 需要手柄列那种交互形态时，用 `vtRowDrag` 并关掉 `editable.reorder`，二选一。

重排本身仍然由核心做：落定只调一次 `moveRow()`，它作用于**原始顺序**并走数据管线，
之后核心自己会派发 `onDataChanged` 与重渲染，甘特顺势把条摆到新行上 ——
所以**不需要**在 `onRowOrderChange` 里调 `refreshGantt()`。

## 命令式 API

装上插件后自动挂到表格实例上，三端（vanilla / React ref / Vue ref）都有类型。

| 方法 | 说明 |
| --- | --- |
| `setGanttZoom(zoom)` | 换粒度，重建时间轴与两级表头 |
| `getGanttZoom()` | 当前粒度（可能因 `maxBuckets` 被降级过） |
| `setGanttRange(start, end)` | 显式设定时间范围。设了就**一直是它**（后续重判不跳回推断值）；两个都传 `null` 回到按数据推断 |
| `getGanttRange()` | `{ start, end }`，末端是开区间上界；时间轴未就绪时 `null` |
| `setGanttMarkers(list)` | 整体替换里程碑竖线 |
| `getGanttMarkers()` | 当前标记列表的副本 |
| `scrollGanttTo(date)` | 横向滚到某个时间，落在**可视时间轴的正中**。它会**撤掉**几何重建时安排的「回到今天」——「换完范围紧接着跳到某天」才不会被下一帧拽回来 |
| `refreshGantt()` | 外部改了行数据后重画。**连表格一起重渲染**（`forceUpdate`）—— 行数据变了意味着表格里那几列显示的也是旧值 |
| `collapseGanttPanel()` / `expandGanttPanel()` / `toggleGanttPanel()` | 收起 / 展开左侧任务表 |
| `isGanttPanelCollapsed()` | 左侧任务表是否处于收起状态 |
| `setGanttBarColor(next \| null)` | 换按列上色的配置（`null` = 不上色），与配置面板的「颜色显示 → 跟随字段颜色」同一份状态 |
| `setGanttProgressField(key \| null)` | 换进度读哪个字段（`null` = 不画进度），与配置面板的「进度显示」同一份状态 |
| `setGanttBarFixedColor(color \| null)` | 所有条一个颜色（`null` = 取消单色）。与 `setGanttBarColor` 互斥 |
| `setGanttFields({ start, end })` | 换「开始 / 结束读哪一列」，只给一个就只换那一个 |
| `setGanttLabelField(key \| null)` | 换「条上显示哪一列」（`null` = 不显示） |
| `setGanttWorkdaysOnly(on)` / `isGanttWorkdaysOnly()` | 工期只数工作日（仅日视图），那几列改画斜线 |
| `setGanttSkipHolidays(on)` / `isGanttSkipHolidays()` | 工期也跳过法定节假日（需要 `holidays`） |
| `setGanttHolidays(list \| null)` | 换假期表 —— 每年的调休安排都不一样，所以它必须能在运行期换 |
| `setGanttNonWorking(fn \| null)` | 换「这天算不算非工作日」。为**补班日**（周六上班）而存在；`null` 回到默认的周六周日 |
