`start` / `end` / `progress` 怎么给，层级用分组还是树形。

## 数据契约

### `end` 是开区间（默认）

```ts no-check
{ start: '2026-08-18', end: '2026-08-20' }   // 默认：两天，条覆盖 18、19 号
```

与 dhtmlx / Bryntum 一致。业务系统里另一种约定同样常见（`end` 表示「做到当天结束」），
猜错的表现是**所有条都短一天**，所以给了显式开关而不是自动猜：

```ts
vtGantt({ start: 'start', end: 'end', endInclusive: true })
// 同样的数据变三天，条覆盖 18、19、20 号
```

`endInclusive: true` 时：

- `start === end` 是「就这一天」的**一天任务**
- `onChange` 回传的 `end` 会**按同一约定换算回去**，写回时不需要自己再加减一天

### 日期格式

`start` / `end` 接受 `Date`、时间戳、`'YYYY-MM-DD'`、以及任何 `new Date()` 能解析的串。

纯日期串按**本地**午夜解析。这不是小事：`new Date('2026-08-17')` 规范上按 UTC 解析，
在东八区会得到 8 月 16 日 16:00 —— 整条左移一天。

只给一端时按零工期处理（即里程碑），比整行不画更接近使用方的意图。两端都没有 → 不画条。

### 进度

`progress` 取 `0..1`。大于 1 的值按百分数处理（`80` → 80%），因为真实数据里两种写法都常见，
猜错的代价（进度条满格）比要求统一格式更小。

### 没有完整日期的行

`start` 与 `end` **两端都要有**，缺一个就不画条 —— 那属于「已立项、还没排期」。
配合 `editable.create` 可以在甘特里点一下把日期点出来。

零工期（`start === end`）画成一条最小 2px 宽的条，而不是特殊形态。

> 早先还有一种「行内里程碑」：零工期任务画成黄色菱形、占一行、能有负责人。
> **整套已移除。** 两个长得像、语义不同的东西摆在一起，除了让人问「这个菱形和那条线
> 有什么区别」之外没有别的效果。现在的分工是：**行 = 有工期的任务**（条），
> **竖线 = 时间轴上的节点**（里程碑）。需要「某个交付物本身也是一行」的话，
> 那就是一条工期很短的任务。

### 层级怎么做：分组 还是 树形

两种都支持，差别不在外观而在**语义** —— 选错了会一直觉得「父级的条不对」。

| | 分组（`groupConfig`） | 树形（`children` 嵌套 + `type: 'tree'`） |
| --- | --- | --- |
| 层级在哪 | **视图**上聚合（数据是扁平的） | **数据**里 |
| 父行是什么 | 纯分类（按阶段 / 负责人 / 状态字段） | 有语义的**工作包** |
| 父行能有自己的日期吗 | **不能**（它是合成行，没有业务字段） | **能** |
| 父行画什么 | 只能是汇总条 | **和叶子一样的普通条** |

**甘特更常见的是分组**：任务本身是平的，层级是看的人临时选的维度（这周按阶段看，下周按负责人看）。

**树形的父节点按普通行处理** —— 它在 WBS 里是个**工作包**，本身就是任务，有计划工期、
负责人、进度，所以画的是它自己的条，和叶子完全一致（可拖、可拉伸、可改进度）。
未排期就留白，在甘特里点一下把日期点出来，与任何一条普通行无异。

这不是「省了个功能」，而是默认值的选择：给它画一条只读的囊括线，等于替使用方断言
「父级不是任务」，而那条线还把「填个日期让它变成正常条」这条路挡住了。

`summaryBars` 三档：

| 值 | 分组行 | 无日期的树父节点 |
| --- | --- | --- |
| `'group'`（默认） | 汇总条 | **不画**（当普通未排期行） |
| `'container'`（`true` 同义） | 汇总条 | 汇总条（MS Project / Bryntum 的行为） |
| `false` | 不画 | 不画 |

树纯粹是分类维度（按模块 / 按负责人挂一层）、父级不承载工期时选 `'container'`。

不论哪一档，**行自己有合法日期时永远画它自己的条**（优先级最高）：「计划的父任务工期」
与「子任务实际占用的范围」是两件事，前者存在就不该被后者顶掉。

汇总条的细节：

- 走 `row.children` 递归，**折叠起来的后代照样计入**（不看当前展示列表）
- 进度取叶子的算术平均
- **不可拖**：它的日期是后代算出来的，没有可写回的目标
- 分组行永远走第 2 / 3 条 —— 它不可能有自己的日期

> ⚠️ 分组形态下别配 `fixedSize: true`：核心的**分组行**比数据行高 2~3px
> （主色标记条 + 加粗标题），与 `estimatedSize` 对不上。行数一多，模型比实际矮的那点
> 累积起来会让最后几行滚不到（核心 AGENTS.md §7.11）。行不等高时就该用不定高 ——
> 条的几何取自真实 DOM 矩形，不定高一样精确。

### 合成行

**展开行**（`renderExpandRow` 合成出来的那一行）不画条 —— 它是上一行内容的附属，
画条会变成同一个任务在相邻两行各有一条。

**分组行**不在此列：它虽然也是合成行，但语义上等同于树形的容器节点（有 `children`、
不可能有自己的日期），所以照样走汇总条那条路。
