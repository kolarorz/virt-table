时间轴列在插件 `setup` 阶段就装上，**首帧即有**，不会先闪一帧没有时间轴的表。

## 一期不做什么

| 不做 | 归属 |
| --- | --- |
| **任务依赖**（FS/SS/FF/SF 箭头） | 二期 —— 一期刻意不做：只画箭头不参与计算，价值有限而视觉噪音大 |
| **行内里程碑**（零工期任务画成菱形） | 已移除，不再规划 —— 与竖线里程碑语义重叠，见「没有完整日期的行」 |
| 工作日历（节假日、多班次）、约束、自动排程联动、关键路径与 Slack | 二期 `Gantt Advanced` |
| 资源行 × 时间的排程视图、事件块重叠分层 | 同地基的另一个 SKU（Scheduler） |
| `end` 之外的多种日期模型（如「工期 + 开始」推导） | 目前用 `end` 取值函数自己算 |

`isNonWorking` 只影响**底纹**，不参与工期计算 —— 一期不排程，跳过周末的工期推算属于二期。

## 已知问题

- 时间桶表头的日期在**纵向**上偏离格子中心约 1px。成因是核心 `.vt-th` 自身的
  `border-bottom: 1px` 落在 `box-sizing: border-box` 内，所有表头单元格都有这个偏移；
  只在甘特这里补正会让日期与相邻的任务列表头**互相错开** 1px，反而更明显，因此没有单独处理。
- 两条里程碑日期很近时，9px 的命中区会重叠，靠后那条更难 hover 到。标签本身不会互相压
  （默认隐藏，一次只显示 hover 的那一条 —— 这也是选 hover 而不是常驻的附带好处）。
- 竖线的 9px 命中区会挡住它下方那一列单元格的点击（条不受影响）。
