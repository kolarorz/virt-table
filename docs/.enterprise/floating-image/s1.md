**开 `viewer` 要引两份 CSS**：本包的 `index.css`，加上核心的
`@virt-table/vanilla/components/image-viewer.css`。查看器的实现与样式都在核心
（与 `VtImage` 共用同一份，本包不复制那 300 行），而库构建会把 CSS 从 JS 里剥出来单独产出
—— `import` 那个 JS 子路径**不会**自动带上它的样式。

为什么不在本包的 CSS 里 `@import` 过来自包含：那样 CSS 与 JS 就会分别来自两个仓库的两个
版本，客户升了核心没升本包就是「新 JS + 旧 CSS」。宁可多一行 import。漏了也不会静默 ——
第一次打开查看器时插件会量一眼浮层的 `position`，不是 `fixed` 就 warn 一行并把该引的路径写给你。

## 坐标是全表内容坐标

| 轴 | 从哪算起 | 滚动时 |
| --- | --- | --- |
| `x` | 内容左缘（**含左侧冻结列的宽度**），与核心 `getColumnRange().left` 同基准 | 横滚时图跟着内容走 |
| `y` | **第一行的上缘**（表头不占 y） | 纵滚时图跟着行走 |

两条都是像素，所以**改列宽、排序、筛选都不会把图挪走** —— 它锚在坐标上，不锚在某一格。
要「跟着某一格走」的图用核心的 `VtImage` 组件或 `cellType: 'image'`，那是另一件事。

定位模式与核心编辑浮层 `.vt-cell-cover` 是同一套：图层挂 `.vt-client`、绝对定位，
每帧（`onScroll` + `onRendered`）按当前滚动状态重摆，横向减 `scrollLeft`、纵向靠每帧
重算的原点跟随（核心的纵向位移归 JS，`scrollTop` 恒为 0）。

原点取核心公开的 `getRowRect(0)`（渲染窗口外的行由核心按行位置账本外推），**不自己拼**
「表体 = stickyHeaderSize + leadingSize − offset」那套残差布局：那是核心的实现细节，
复制一遍就等着核心改摆法的那天炸掉。空表时它返回 `null`，
退化成量表头下沿 —— 水印类用法在空表上也得看得见。

## 三个手势 + 看图，各有开关

| 选项 | 默认 | 行为 |
| --- | --- | --- |
| `draggable` | **`true`** | 按住图身拖动，**拖到容器边缘自动滚动** |
| `resizable` | `false` | 四角把手；Shift 等比。会把算出来的 `height` 写回配置 |
| `rotatable` | `false` | 顶边上方圆钮；Shift 吸附 15°。绕**中心**转，`x` / `y` 不变 |
| `viewer` | `false` | 点一下打开查看器（缩放 / 旋转 / 平移 / 前后切换） |
| `downloadable` | `false` | 查看器工具栏给下载按钮（`viewer: false` 时无意义） |
| `edgeZone` / `scrollSpeed` | `40` / `8` | 自动滚动的触发距离与速度（`edgeZone: 0` 关掉） |
| `zIndex` | `4` | 图层层级：`3` 滑到冻结列之下，`4` 盖住冻结列但让位给编辑浮层，`7`+ 盖住表体一切浮层 |
| `texts` | — | 查看器文案；不传就取表格当前的 `locale.imageViewer`，**跟随 `setLocale()`** |
| `onChange(image, { action, done })` | — | `action: 'move' \| 'resize' \| 'rotate'`；手势中每次移动报 `done: false`，松手补一次 `done: true` |

每张图还能单独 `locked: true`：**一切交互关掉且指针事件穿透**，底下的单元格照常框选、
双击编辑 —— 水印类用法就该这么配。四个开关都关掉的图同样自动穿透（不然它只是白挡着）。

### 实例 API

```ts no-check
table.addFloatingImage({ id, src, x, y, width });
table.updateFloatingImage(id, { x, y, width, height, rotate, locked });  // 找不到 id 返回 false
table.removeFloatingImage(id);
table.setFloatingImages(list);          // 数组顺序 = 叠放顺序
table.getFloatingImages();              // 配置副本，改它不影响表格
table.openFloatingImageViewer(id?);     // 程序化看图，viewer: false 时也能用
```

类型由包末尾的 `declare module '@virt-table/vanilla'` 注入，所以 React 的 `ref` 与
Vue 的实例上都有（vanilla 直接挂在实例上）。

## 几件需要知道的事

**中间那层 `.vt-floating-layer` 不是装饰。** 图片不直接挂 `.vt-client`，垫了一层
`overflow: hidden` 的图层 —— 绝对定位子节点是**计入** scrollport 滚动范围的，一张摆在
右边的图会凭空撑大 `scrollWidth`，而横向滚动条（读 `scrollWidth`）与表头（宽度按列宽之和）
都不知道，结果是能滚进表头右侧的一片空白。图层的盒子严格等于可视区
（`width/height: 100%` 对 scrollport 取的是可视尺寸），溢出被它自己裁掉。
CDP 实测：把图挪到 `x = 20000`，`.vt-client.scrollWidth` 一动不动。

**移动手势记的是「抓取偏移」，不是「起点 + 位移」。** 自动滚动时**指针不动而内容在动**，
按位移算的话图会被内容带着跑、脱离指针。每次更新按「当前指针的内容坐标 + 抓取偏移」重算，
自动滚动的每一帧复用同一个函数。CDP 实测：按住图停在下边缘，内容滚过 960px，
图的 `style.top` 一动不动（始终钉在指针下）。

**只有移动带自动滚动。** 缩放 / 旋转改的是图自身的形状，锚点是对角或中心 —— 内容一滚，
屏幕位移与形变的对应关系就错了。

**把手常驻，不是 hover 才出。** 第一版做成 `visibility: hidden` + `:hover` 显形，
CDP 一测就废：隐藏元素不参与命中测试，而**旋转钮在图的盒子外面**（上方 26px），
指针一离开图的盒子 `:hover` 立刻失效、把手又藏回去，中间只剩 1px 的连接线可踩
（实测表现是「按下去什么都没发生，反而把表格拖着横滚了 16px」）。现在常驻 + 不透明度分档
（0.75 → hover / 手势中 1.0）；顶上腾不出 26px 时钮自动翻到图的下边，否则会被图层裁掉、
那张图再也转不了。

**可交互的图会吃掉指针事件**，它盖住的格子点不到；触屏上还带 `touch-action: none`，
所以图片那块区域不能用来滚表格。要点底下的格子就先挪开或 `locked: true`。

**没有键盘等价物。** 让图片进 Tab 序的代价太大：十万行的表里 Tab 会先撞上它，拿到焦点后
方向键还会与核心 `vtKeyboardNav` 的走格抢按键。程序化改一切走 `updateFloatingImage()`。

**改宽度时记得清 `height`。** 拖过四角把手之后配置里会留下一个算出来的 `height`，
此后只改 `width` 会把图拉变形；想回到「按图片自身比例」就在 patch 里显式传
`height: undefined`。

## 纯几何层单独可用

```ts
import { floatingImageBox, resizeFromCorner, toLocalDelta } from '@virt-table-pro/floating-image/geometry';
```

对核心零依赖、对 DOM 零依赖：定位换算、位移投影、拖角缩放时「对角钉在原地」的闭式补偿。
服务端预算「这张图落在哪一格上」，或者拿这套数学写自己的编辑器都行。也是本包唯一能在
无布局环境里测死的部分（happy-dom 的 rect 全是 0，其余靠 CDP 手验）。
