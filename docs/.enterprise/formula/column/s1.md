复杂逻辑不想写表达式时，直接给函数：

```ts
vtFormulaColumn<Row>({
  columns: {
    tax: 'ROUND(amount * 0.06, 2)',
    label: (row) => `${row.dept} / ${row.city}`, // 逃生口，拿到整行
  },
});
```

## 结果写回行数据，所以能排序、能筛选、能导出

求值结果写进 `row[colKey]`（而不是只改渲染）。核心的排序/筛选/导出/复制走的都是 `row[key]`，
所以一律照常工作 —— **纯 `col.render` 做不到这一点**。

写回是安全的：核心的数据管线对无 children 的扁平行返回同一引用，改的就是使用方那份原始行对象。

## 求值时机：一处必须知道的别扭

核心的构造函数在插件 `setup` **之前**就跑完了首屏管线，而插件最早只能在 `setup` 里动手。所以：

- **显示**从第一帧起就是对的（`setup` 里算完，首帧渲染在其后）
- 但首屏那次**排序/筛选**是在「公式列还没有值」的情况下跑的

因此当**初始排序或初始筛选涉及公式列**时，插件会在 `onMounted` 里补一次管线重算（把当前
sort / columnFilters 原样回灌）。只补这一次，代价是使用方的 `onSortChange` / `onFilterChange`
会多收到一次同值回调。

**换数据时最干净的用法是先算再进表**，这样管线第一次就用到真值：

```ts
table.evaluateFormulas(nextRows); // 先把公式列算好
table.setList(nextRows); // 再进表
```

改了源字段（直接改行对象）之后要说一声，核心不知道行对象被改了：

```ts
for (const row of rows) row.amount += 1000;
table.recalculateFormulas(); // 重算 + 必要时重跑管线 + 重画
```

根治要核心补一个 **pre-pipeline 钩子**（数据管线开跑之前的介入点），这条已在排期上。

## 配置项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `columns` | `Record<string, string \| ((row: T) => any)>` | **必填** | 列 key → 公式。key 必须是**已存在的列**或行数据里的字段 |
| `functions` | `Record<string, FormulaFunction>` | — | 自定义函数（覆盖同名内置），名字大小写不敏感 |
| `autoEvaluate` | `boolean` | `true` | 数据变化时自动重算。关掉 = 只有 API 调用才算 |
| `onError` | `(info: { colKey, code, detail }) => void` | — | 编译或求值出错时回调，**每列每种错误只报一次** |

自定义函数与内置函数清单见 <ProLink to="formula/expression">表达式语法</ProLink>。

## 实例 API

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `evaluateFormulas(rows?)` | `number` | 对一批行求值并写回，返回**写回的格数**。不传则算当前数据 |
| `recalculateFormulas()` | `number` | 全量重算当前数据；有变化则重画，排序/筛选吃到公式列时重跑管线 |
| `setColumnFormula(colKey, formula)` | `boolean` | 运行时换公式（传 `null` 或 `''` 撤掉这一列），随后自动重算 |
| `getColumnFormula(colKey)` | `string \| null` | 公式原文；函数形式返回 `'(function)'` |
| `getFormulaErrors()` | `Record<string, { code, detail }>` | 编译期错误。UI 可据此在表头挂警告图标 |

```ts
// 做一个「公式可编辑」的表头
input.addEventListener('change', () => {
  const ok = table.setColumnFormula('tax', input.value);
  if (!ok) {
    const err = table.getFormulaErrors().tax;
    showError(`${err.code} ${err.detail}`);
  }
});
```

## 循环引用

列之间成环的，**编译期**就钉成 `#CIRCULAR!`，不会栈溢出：

```ts
table.setColumnFormula('total', 'tax + 1');
table.setColumnFormula('tax', 'total * 0.5');
// tax 与 total 两列都显示 #CIRCULAR!；解开任一条即自动恢复
```

## 第一档**没有**什么

A1 记法、区域引用（`SUM(B2:B10)`）、跨行/跨表引用。`SUM` 在这里吃的是**参数列表**：
`SUM(amount, tax)`。要区域就用 <ProLink to="formula/cell">单元格公式</ProLink>。
