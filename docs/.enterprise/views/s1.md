不想用自带面板就纯用 API，自己的 UI 想怎么做都行（**命令式 API 三端一致**，都挂在实例 / ref 上）：

```ts
table.saveView('本月对账'); // 存当前状态（同名 = 覆盖）
table.listViews(); // [{ name, state, createdAt, updatedAt }, ...]
table.applyView('本月对账'); // 一次 setState 应用回去
table.deleteView('本月对账'); // 删视图，**当前表格状态不变**
table.getCurrentView(); // '本月对账' | null
```

## 一个视图里存了什么

就是核心的 `VirtTableState`，不多不少：

| 字段 | 内容 |
| --- | --- |
| `version` | 结构版本。`setState()` 遇到不认识的版本会告警并**整体忽略** |
| `columns` | 叶子列的 `{ key, width, hidden }`，**数组顺序即列序**（含隐藏列，位置也能还原） |
| `sort` | 排序，多列排序时数组顺序 = 优先级 |
| `columnFilters` | 列头筛选：列 key → 勾选值 |
| `filterModel` | 高级筛选条件树 |
| `pagination` | `{ page, pageSize }`（`total` 不进状态，它是派生的） |

数据本身**不在**视图里 —— 视图描述的是「怎么看这批数据」。

## 配置项

| 选项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `storageKey` | `string` | `'virt-table-views'` | localStorage 的 key。**多表场景必改** |
| `storage` | `ViewsStorage` | localStorage 适配器 | 自定义存储。传了它 `storageKey` 忽略 |
| `placement` | `'anchor' \| 'top-right'` | `'anchor'` | 面板位置。`'anchor'` 需要给 `openViewPanel(anchor)` 传按钮 |
| `texts` | `Partial<ViewsTexts>` | 中文 | 面板文案 |
| `onViewChange` | `(name, view) => void` | — | 应用了某个视图后触发；`name === null` 表示当前视图被删掉了 |

文案键：`panelTitle` / `empty` / `namePlaceholder` / `saveCurrent` / `deleteLabel` / `overwriteHint`。

```ts
vtViews({
  placement: 'top-right',
  texts: {
    panelTitle: 'Views',
    empty: 'No saved views',
    namePlaceholder: 'View name',
    saveCurrent: 'Save current',
    deleteLabel: 'Delete',
    overwriteHint: 'Same name overwrites',
  },
});
```

## 实例 API

| 方法 | 返回 | 说明 |
| --- | --- | --- |
| `saveView(name?)` | `boolean` | 存当前状态。不传名字则覆盖当前已应用的视图；两者都没有则 warn 并返回 false |
| `applyView(name)` | `boolean` | 应用视图。视图不存在或 `setState` 拒绝时 false |
| `deleteView(name)` | `boolean` | 删视图。**表格当前状态不动** |
| `listViews()` | `SavedView[]` | 全部视图的**副本**（外部改了不影响插件内部） |
| `getCurrentView()` | `string \| null` | 当前已应用的视图名 |
| `exportViews()` | `string` | 全部视图的 JSON 串，可直接 POST 给服务端 |
| `importViews(json)` | `boolean` | 用一份 JSON **整体替换**视图列表。坏条目逐条过滤，整份解析不了则拒绝 |
| `openViewPanel(anchor?)` | `void` | 打开面板（点外面或 Esc 关掉） |
| `closeViewPanel()` | `void` | |
| `toggleViewPanel(anchor?)` | `void` | |
| `isViewPanelOpen()` | `boolean` | |

## 共享视图：接服务端

存储适配器**刻意是同步接口**。把整套 API 染成异步会让 `applyView()` 这种「点一下就该立刻生效」
的操作变成 Promise，UI 侧还得处理加载态与竞态。正确姿势是**读走异步、写走同步**：

```ts
const KEY = 'orders-table';

const table = new VirtTable(el, {
  list: rows,
  columns,
  itemKey: 'id',
  estimatedSize: 40,
  plugins: [
    vtViews({
      storage: {
        // 同步读本地那份，先让界面有东西
        loadViews: () => JSON.parse(localStorage.getItem(KEY) ?? 'null'),
        // 写：本地留一份 + 异步推给服务端。失败了本地也不会丢
        saveViews: (views) => {
          localStorage.setItem(KEY, JSON.stringify(views));
          void fetch('/api/views', { method: 'POST', body: JSON.stringify(views) });
        },
      },
    }),
  ],
});

// 启动后把服务端那份灌进来（整体替换）
fetch('/api/views')
  .then((r) => r.text())
  .then((json) => table.importViews(json));
```

`ViewsStorage` 只有两个方法：

```ts
interface ViewsStorage {
  loadViews(): SavedView[] | null;
  saveViews(views: SavedView[]): void;
}
```

默认的 localStorage 适配器读写全部 try/catch：Safari 隐私模式下 localStorage 存在但一写就抛，
SSR 下压根没有。两种情况都降级成「视图只在本次会话里有效」，绝不让保存视图这种辅助功能炸掉表格。

## 几件需要知道的事

**同名 = 覆盖，不是新增。** 用户点同一个名字保存两次，意图显然是更新。面板里的输入框
title 就写着这句。

**不做脏检查。** 应用视图后拖了列宽，`getCurrentView()` 仍返回原视图名。要判断「是否偏离已保存
状态」得深比较整个 state，成本不低而收益很薄 —— 用户点保存时同名覆盖即可。

**删视图不重置表格。** 删掉当前视图后列宽/排序保持原样，只是 `getCurrentView()` 变成 `null`
并触发一次 `onViewChange(null, null)`。

**跨版本的旧视图会被整体忽略。** `setState()` 校验 `version`，不认识就告警并跳过 ——
所以升级核心之后老视图可能失效，这是核心的约定，不是本插件在兜。

**列已经不存在的视图会被部分应用。** `setState` 只应用它认识的字段与仍存在的列，
不会因为少了一列而整份作废。

## 面板样式

面板挂在 `ctx.rootEl` 里，类名前缀 `vtp-views-`：

```
.vtp-views-panel        面板容器（定位由插件按锚点算）
  .vtp-views-title      标题
  .vtp-views-list       列表滚动区
    .vtp-views-empty    空态文案
    .vtp-views-item     一行（--active 是当前视图）
      .vtp-views-apply  视图名按钮
      .vtp-views-del    删除按钮
  .vtp-views-save       底部保存区
    .vtp-views-input / .vtp-views-save-btn
```

全部读核心的设计令牌（`--vt-bg-elevated` / `--vt-border-color` / `--vt-color-primary` …），
跟着主题走，不需要单独适配深色。
