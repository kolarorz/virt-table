# 电子表格

一份 **10 万行 × 65 列（650 万单元格）** 的工程排期台账，外加 **2.7 万个合并区**：

- 13 个语义列（工单号 / 模块 / 子任务 / 负责人 / 状态 / 优先级 / 进度 / 工时 / 偏差 / 验收 / 截止日期 / 备注）+ 52 个周计划列；
- 每一列都是**内置单元格组件**：负责人是头像胶囊、状态与优先级是彩色胶囊下拉、验收是可点勾选框、进度是进度条、截止日期是日历、工时与周计划是数字输入；
- 模块列每 4 行纵向合并，每 40 行一条横向「阶段小结」带 —— 合起来 2.7 万个合并区；
- 框选、复制粘贴、合并/取消合并、键盘导航、全表搜索、导出选区都能用；
- **偏差列整列是公式**（`=I{n}-H{n}`，共 9.75 万条）：改实际工时它跟着变，顶部那条 fx 栏可以给任意一格写公式（`=SUM(N2:BM2)` 之类）；
- **编辑、清空、合并、粘贴都能撤销**（Ctrl/Cmd+Z），撤销栈里那几条标签就是「编辑 I3」「粘贴 2 行」这种人话；
- 表上还浮着一张**可拖拽 / 缩放 / 旋转的现场平面图**，点一下能看大图并下载，坐标与角度可以在顶部直接改。

后三项是**企业版插件**（见下面那一块），本页用一把域名绑定的演示密钥授权运行。

页面顶部那条统计一直在更新，它就是这个案例要证明的东西：

```
100,000 行 × 65 列 = 6,500,000 格 · 合并区 27,499 · 逐格数据只存了 2,564 格
· 公式 97,500 条 · 造数 157ms + 建表 450ms · DOM 里常驻 26 行 / 432 格
```

（不装公式插件时建表是 **53ms**；那多出来的约 400ms 是公式的装载代价，下面「单元格公式」一节说清了它花在哪、为什么值。）

650 万格的表，DOM 里常驻的单元格只有几百个（宽屏铺开更多列时上千）；随便跳到第 5 万行是**算出来**的，中间那 5 万行从没进过 DOM。

## 本案例中涉及企业版功能

[**单元格公式** · `@virt-table-pro/formula`](/enterprise/#formula)

- 偏差列整列是公式：`=I{n}-H{n}`，共 9.75 万条
- 顶部 fx 栏：给当前格写公式，A1 记法

- 依赖图 + 增量重算：只算受影响的那几格
- 公式格左上角蓝三角，出错显示 `#DIV/0!` 一类错误码

- 覆盖单元格编辑、公式写入、清空选区、合并/取消合并、粘贴
- 一次编辑记一条（不是一次按键一条）
- 按钮上的 tooltip 直接说「撤销：粘贴 2 行」
- 列宽/列序/显隐这类查询状态由插件自动入栈

[**浮动图片** · `@virt-table-pro/floating-image`](/enterprise/#floating-image)

- 浮在全表之上的现场平面图
- 拖动，拖到容器边缘自动滚动
- 四角把手缩放、顶部圆钮旋转
- 点一下打开查看器，工具栏可下载
- 锁定档：指针事件穿透（水印用法）

## 撑住这个规模的三个决定

**1. 数据只存值，外观按规则派生。** 逐格数据（`_sheetCells`）只用在表头行与小结带那两处——那里的外观是**内容本身**，推不出来；10 万行明细只存**纯值**，胶囊、勾选框、数据条、热力图、逾期红字都在渲染时按列的语义算出来。给 650 万格每格存一个 `SpreadsheetCellData` 的话，光对象构造与内存就够毁掉首屏——而真实系统里「条件格式」本来也是规则，不是数据。统计条里那句「逐格数据只存了 2,564 格」就是这个决定的度量。

**2. 行对象是稀疏的。** 生成的行不预填 65 个空字符串键，只写真正有值的那 27 个（13 个语义列 + 14 个有工时的周；渲染取不到就是空）。10 万行因此是 270 万次属性写入而不是 650 万次，造数 144ms。

**3. 每一列都是内置单元格组件。** 语义列各用自己的那个（见上表），其余用 `VtInput`——外观、编辑器、锁高契约全部来自组件，demo 里没有一行自己拼的控件或标签 HTML。两处细节值得看：**进度列取了两个组件的各一半**（`VtNumberInput` 的编辑器 + `VtProgress` 的渲染），既能像数字一样改又显示成进度条；**表头行与小结带存了逐格数据**（富文本 + 底色），必须优先于组件渲染，否则 `VtSelect` 会把表头那格的「状态」两个字也画成一枚胶囊。

选区按合并扩张用核心的 `table.expandSelectionForMerges()`，合并区状态只存在表格里（`getMerges()` / `setMerges()`）。demo 自己不再留一份平行实现。

## 单元格公式 <Badge type="warning" text="付费插件" />

「偏差」这一列本来就是**算出来的**：实际工时减预计工时。之前它是造数时算一遍存下来 ——
改了实际工时它就过期。现在它整列是一条公式：

```ts
// 造数时直接把原文写进格里，插件装载时搬进 _formulas 并算一遍
row.J = `=I${r + 1}-H${r + 1}`;   // A1 的行号 = 数据下标 + 1（第 1 行是表头行）

vtFormula({
  columns: FORMULA_COLS,   // 全部 65 列，顺序即列字母
  editor: false,           // 写公式的入口是顶部那条 fx 栏，见下
  onActiveCellChange: syncFx,
  onRecalculated: ({ changed }) => setStatus(`增量重算：写回 ${changed} 格`),
})
```

四处值得单独说：

**1. 列字母不是插件编的，是这个案例本来就有的。** 65 列的 key 就是 `A`…`BM`（`colIndexToKey`），
所以 `columns` 给**全部 65 列**：列字母 = 列标题 = 列 key，公式里写 `I2` 指的就是表头上那个 I。
只把数字列挑进去的话字母会按数组下标重排（`H` 变成 `A`），fx 栏里的坐标就没人看得懂了。
序号列（`type: 'index'`）不参与 —— 功能列不承载数据，不该占用列字母。

**2. 写公式的入口是 fx 栏，不是格子。** 这个案例每一列都有自己的单元格组件（数字框、日历、
胶囊下拉），公式插件不会去覆盖别人的 `renderEditor`（案例里 `editor: false` 把这件事写明白）。
于是双击进的仍然是那些组件，写公式另开一个入口 —— 正好也是电子表格用户最熟的那个位置：
左边显示当前格的 A1 坐标，点公式格时显示**原文**、点普通格显示**当前值**。
点到公式格还会把它引用的格用虚线框出来（Excel 的 range finder），`=I2-H2` 一眼看得出钱是从哪两格来的。

**3. 结果写回格里，原文另存一份。** 装载后 `row.J` 是**数字**、`row._formulas.J` 是 `'=I2-H2'`。
所以红绿条件格式、复制、导出、求和全都零成本正确 —— 它们读的还是值，没有一行渲染代码需要改。
清掉一格时要连 `_formulas` 一起清（案例的「清空选区内容」就是这么做的），否则引擎下一轮又把结果算回来。

**4. 代价是一次全表扫描，之后都是增量。** 装公式插件后建表从 **53ms → 450ms**：`compile()` 要遍历
650 万格找出哪些是公式（这是它建依赖图的唯一办法），再把 9.75 万条求一遍值。
这笔钱只在装载时付一次；之后改任何一格走的是 `recalcFrom` —— 改 I3 时状态栏报的是「写回 1 格」，
不是 9.75 万条。首屏在意这 400ms 的话，把公式收窄到真正需要的那些行就行。

::: warning A1 记法与排序/筛选不能同时要
行号绑的是**数据下标**，而表格的行序是视图。这个案例因此不开排序与筛选（装了插件又开排序，
它会 `console.warn` 说明公式会指到别人身上）。反过来说：需要排序的表就该用另一档
（`vtFormulaColumn` 计算列，结果写回行数据，跟着行走）。
:::

## 撤销 / 重做 <Badge type="warning" text="付费插件" />

Ctrl/Cmd+Z（或顶部那两个按钮）能退回**五类**动作：单元格编辑、fx 栏写公式、清空选区、
合并/取消合并、粘贴。按钮的 tooltip 就是栈顶那条标签 —— 「撤销：粘贴 2 行」。

插件是**两层机制**，而这个案例的活全在第二层：

- **自动层**：列宽 / 列序 / 列显隐 / 排序 / 筛选 / 分页。这些都在核心的 `getState()` 里，插件自己比快照就行。
- **手动层**：数据变更。核心**没有任何编辑事件**（`renderEditor` 返回的控件由使用方自己写回行数据，
  核心根本不知道发生了什么），所以插件不可能自动捕获 —— 猜不出来的东西不猜，改由使用方说一声。

于是「撤销的粒度」变成案例自己的设计，四处各不相同：

| 动作 | 快照粒度 | 为什么 |
| --- | --- | --- |
| 单元格编辑 | 一格的旧值/新值，**一次编辑一条** | 组件每次按键都写回，逐键记的话按十下键要撤销十次 —— 那不是用户心里的一步 |
| fx 栏写公式 | 那一格的**原文**（不是算出来的结果） | 撤销要还原的是输入。还原结果值等于把公式变成常数 |
| 清空选区 | 逐格：值 + 逐格数据 + **公式原文** | 三样都清了才叫清空，也就都得记；漏了原文的话「撤销」会看起来只回来一半 |
| 合并 / 取消合并 | 整份 `merges` 数组 | 合并区状态只有一份且很小，整份换比算差集省事又不会错 |
| 粘贴 | **受影响的整行**浅拷贝 + 整份 `merges` | 粘一次会动一片矩形、可能顺手加列、还会带进来合并区；逐格记要把三样分别对齐，整行一把全覆盖 |

编辑的**边界**是这么划出来的：列上包一层 `renderEditor`（编辑器打开的那一刻 = 「变更前」），
`onChange` 里更新「变更后」并只在第一次写回时记一条 —— `redo` 的闭包读的是那个会被后续按键
覆盖的变量，所以重做回到的是这次编辑**最后**那个值。

```ts
col.renderEditor = (ctx) => {
  editRecorder?.begin(ctx.row, key);   // 编辑器打开：记下变更前
  return innerEditor(ctx);
};

// 组件写回（每次按键都来）
onChange: (value, row) => {
  editRecorder?.commit(row, key, value);   // 更新「变更后」；同一次编辑只进历史一条
},
```

「点一下就切」的 `VtCheckbox` 不开编辑器，所以它没有 `begin` —— 布尔的「变更前」就是取反，不用猜。

快捷键默认挂在**表格根元素**上（`hotkeys: 'root'`）：焦点在表格里才响应，不会劫持整页的 Cmd+Z。

## 浮动图片 <Badge type="warning" text="付费插件" />

表上浮着一张「现场平面图」：按住能拖（**拖到容器边缘会自动滚动**）、悬停出把手（四角缩放、顶部圆钮旋转）、点一下打开查看器（工具栏带下载）。顶部四个框（x / y / 宽 / 角度）与这些手势**双向绑定** —— 手势一动框里的数字就跟着变，改框里的数字图就跟着变。

::: warning 这一页是怎么把付费插件跑起来的
本页**通过授权装载**：案例里 `setLicenseKey()` 用了一把**域名绑定**的演示密钥（只覆盖 `floating-image` / `gantt` / `formula` / `undo` 四个演示产品）。密钥公开写在源码里是安全的 —— 换个域名校验就不通过，右下角出现未授权角标 + 一行 warn，但**功能一点都不降级**（付费插件的铁律：只 warn，绝不抛错、绝不禁用）。

授权模式与常见问题见 **[企业版](/enterprise/)**（本页三个付费插件：[公式](/enterprise/#formula) · [撤销重做](/enterprise/#undo) · [浮动图片](/enterprise/#floating-image)）；报价或私有部署：keno.lee@foxmail.com。
:::

它走的是 `vtFloatingImage`，和电子表格里「插入图片」是同一个心智模型：

```ts
vtFloatingImage({
  images: [{ id: 'site-plan', src: '…', x: 560, y: 120, width: 300 }],
  resizable: true,      // 四角把手缩放（Shift 等比）
  rotatable: true,      // 顶部圆钮旋转（Shift 吸附 15°）
  viewer: true,         // 点一下打开查看器 —— 复用 VtImage 那一套
  downloadable: true,   // 查看器工具栏给下载按钮
  // 手势中每次移动都报（done: false，用来实时回显），松手补一次 done: true（该落库了）
  onChange: (img, { action, done }) => { … },
})
```

**坐标是全表内容坐标**：`x` 从内容左缘算起（含左侧冻结列的宽度），`y` 从**第一行的上缘**算起。所以横滚纵滚它都跟着内容走，而改列宽、排序、筛选都不会把它挪走 —— 它锚在一对像素坐标上，不锚在某一格。要「跟着某一格走」的图请用 [`VtImage` 组件](/vanilla/examples/cell/vt-image)。

四处细节值得单独看：

- **定位模式与「编辑浮层」`.vt-cell-cover` 是同一套**：浮层挂在 `.vt-client`（滚动视口）上，横向减掉 `scrollLeft`、纵向靠每帧重算的原点跟随（纵向位置归 JS，`scrollTop` 恒为 0，见[滚动模型](/vanilla/examples/advanced/scroll-model)）。
- **默认压在编辑浮层之下**（图层 `z-index: 4`，编辑浮层 5）：图片底下那一格双击进编辑时，编辑框不该被图片挡住；同时它**盖住冻结列**（冻结列也是 4，同值时后插入的图层取胜）。
- **只有「移动」带边缘自动滚动**（走 `internal/auto-scroll.ts`，与框选、行拖拽同一份实现）：移动的目的地经常在视口外，而缩放 / 旋转改的是图自身的形状，滚动只会让手上的锚点跑掉。
- **可交互的图会吃掉指针事件**，所以它盖住的格子点不到 —— 要点就先把图挪开，或者勾上「锁定」（`locked: true`：三个手势与看图一起关掉、指针事件穿透，水印类用法都该这么配）。

图片查看器**不是**付费部分：它就是核心 `VtImage` 用的那一个（公开子路径 `@virt-table/vanilla/components/image-viewer`），付费插件只是复用它 —— 见[图片列示例](/vanilla/examples/cell/vt-image)。

图片本身是 data URI 生成的 SVG，demo 不依赖外网。

## 统计条是怎么来的

「DOM 里常驻多少行/多少格」「滚动中最长一帧多少毫秒」由一个**内联插件**报出来 —— 也是这个案例里唯一自己写的插件：

```ts
function vtSheetStats(report) {
  return {
    name: 'demoSheetStats',
    setup(ctx) {
      // onRendered 是整帧渲染完成的准确时机（_patch 末尾），此刻数 DOM 才不会数到半帧
      ctx.on('onRendered', () => report(count(ctx)));
      // 帧率只在滚动期间用 rAF 间隔算：空转的 rAF 本身就会污染它要测的东西
      ctx.on('onScroll', startBurst);
    },
  };
}
```

钩子必须走 `ctx.on(...)` 注册——`PluginHandle` 上没有 `hooks` 字段，返回 `{ hooks }` 会被静默忽略（写这个案例时踩过，统计条一直空白）。
