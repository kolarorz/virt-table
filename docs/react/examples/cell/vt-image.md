# React VtImage 图片

缩略图 + 点开图片查看器。**取图不在渲染路径上**：`render` 只同步产出占位方框，加载排到空闲期，
单元格被回收就丢弃任务 —— 快滚一屏不浪费一次请求，也不会在滚动帧里解码。

## 说明

**「纯展示」类组件**：不改行数据，所以没有 `renderEditor`、也**不需要 `vtCellEditor` 插件** ——
与 `VtLink` 同档（点了有反应，但反应不是改值）。

### 异步加载的三条机制

行 DOM 是池化的（每次重绘都新建单元格内容），所以在 `render` 里同步 `new Image()` 等于**每个滚动帧
都在发请求 + 在主线程解码**。核心的 `cellType: 'image'` 就是那种同步的一张图，适合「一列小图、数据量
不大」；图多、行多、要看大图用这个组件：

| 机制 | 做了什么 |
| --- | --- |
| 空闲期排期 | `requestIdleCallback`（不支持时退定时器）里才开始取图，滚动帧里一次请求都不发 |
| 回收即弃 | 占位盒离开文档就丢弃任务（`isConnected` 是唯一能问的探针 —— 虚拟滚动回收单元格时不发任何通知） |
| 先进先出 + 出队前剔废 | 进队顺序就是行序，所以图从上往下出。滚走的格子早被回收，出队时 `alive()` 一查就跳过（连请求都不发）—— 所以不需要用「后进先出」去躲废任务，那样只会让图从最后一行往上冒 |
| 并发上限 4 | 再多也只是排在浏览器的连接队列里，还会让解码堆在一起 |

解码走 `img.decode()`：解码在浏览器自己的线程完成，元素插进单元格的那一帧不会卡。
加载失败的 URL 记进坏链表，滚回去不再重试（成功的图交给浏览器自己的缓存，不另记一份）。

### 缩略图尺寸只跟行高走

组件**刻意没有 `size` 选项**：缩略图写死 56px 会把 40px 的行顶到 75px，而 `estimatedSize` 还是 40
——十万行量级下会滚不到底（这条不变量见[行高等式](/vanilla/examples/basic/theme#行高等式)）。要大缩略图就把**行**配高：
在容器上设 `--vt-density-line-height`，同时把 `estimatedSize` 改成「内容高 + 上下内边距 + 1px 下边框」。
示例顶部那颗按钮就是这么切的（21 / 40 ⇄ 48 / 67）。

### 查看器

自绘浮层，挂在 `.vt-root` 内（所以 `--vt-*` 令牌与暗色主题自动跟随），铺满视口：
滚轮或 `+` `-` 缩放 · 拖拽平移 · 双击放大 · 旋转 · `←` `→` 换图（首尾循环）· `Esc` / ✕ / 点图外的幕布关闭。
`+N` 点开时从被折叠的第一张开始看。

**多图还会给一条底部列表条**：一排小图、当前那张主色描边，点一下直达 —— 光有 `←` `→` 与
`3 / 8` 的话，「跳到第 6 张」要按五次，也看不出别的几张长什么样。小图走同一条取图队列，
并且**排在大图后面进队**（正在看的那张必须先出来）。

滚轮缩放按 `deltaY` 连续换算（不是「一次事件一档」）：触控板一次两指滑动会连发几十个
`wheel`，按档乘会瞬间顶到最大。

## 相关 API

| 字段 | 作用 |
| --- | --- |
| `maxCount` / `fit` | 最多画几张（超出折叠 `+N`）、缩略图裁切方式 |
| `items` / `separator` | 自定义取图；拼接字符串的分隔符（**默认不拆** —— data URI 里就有逗号） |
| `viewer` / `downloadable` / `onPreview` | 关掉查看器、给下载按钮、拦下内置查看器自己接管 |
| `texts` | 查看器文案 |
